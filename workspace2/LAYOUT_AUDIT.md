# Data-layout audit

## Status and reproducibility

This audit began as a measurement lab. It now also records measured production changes where an
owner and end-to-end evidence justified them; all other candidates remain lab evidence rather than
production recommendations.

Run the baseline with `sh layout-lab/run-baseline.sh`. The raw result is
[baseline-aarch64-apple-darwin.tsv](layout-lab/raw/baseline-aarch64-apple-darwin.tsv).

[locality-validation-m3-pro.jsonl](layout-lab/evidence/locality-validation-m3-pro.jsonl).

It was generated by Rust 1.97.1 for 64-bit ARM macOS. The table reports `size_of`, `align_of`, a
64-byte cache-line occupancy calculation, and public field offsets. A cache line is a reporting
assumption, not a portability promise or a cache-miss measurement.

`repr(C)` and `repr(transparent)` types with existing exact-layout tests are marked as such. Every
other layout is compiler-and-target discovery only. It must not become a public format commitment.
Private implementation records stay private; the owner will provide an explicit nightly
`-Zprint-type-sizes` dump when a nightly toolchain is available.

The nested lab has no production dependency changes. It has a visible, non-production
`UnsafeCell<MaybeUninit<_>>` permit-slot candidate and a scoped allocator wrapper solely to test
the unsafe proof and allocation claims against safe references. Neither is recommended for a
shipping crate.

## Profiles and missing metrics

Portable-client measurement is one current root, mostly resident/local borrowed bytes, 0/1/4 object
metadata, bursty range demand, remote absence, and cancellation. It must count root, locality,
reusable scratch, store metadata, held leased input, prepared-frame stack, and no-op observation.

Remote-service measurement is concurrent admission, larger roots, sustained streaming, bounded
payload store, high waiter/terminal occupancy, and mixed locality. It reports per-request plus
aggregate table/payload bytes, every core or shard, and false-sharing evidence.

Both profiles cover `0`, `1`, inline maximum, inline maximum plus one, typical, p95/p99, and each
protocol maximum. The generated table is not a performance result: allocation count/bytes, peak live
bytes, branch/cache counters, code size, CPU time, and end-to-end traces remain unmeasured.

## Runtime storage and waiter evidence

The current remote runtime is 144 B on this target; its `Admission` and `Owner` are each one 8-B
borrow, and `AdmissionFuture<u64, u64>` is 48 B. Those are compiler discoveries, not ABI promises.
Remote payload/waiter tables reserve before admission, inline tables encode both capacities in the
type, and local tables borrow caller arenas for the entire runtime lifetime. There is no terminal
queue: a permit-addressed payload cell changes from queued work to a typed terminal and is reclaimed
only after terminal observation.

The dense waiter record remains 40 B in the laboratory. The active-bitmap and size-class candidates
can reduce inactive scans, but add publication, stale-membership, and fairness obligations; they are
not adopted without a measured sustained-contention win. The shipping registry has Loom coverage for
register/arm/recheck/wake/cancel/reuse, while the scoped Miri job covers partial caller-arena
initialization, in-place terminal reuse, drop, and handle reuse. This evidence establishes safety and
conservation, not a hardware throughput claim.

## Competing-suite status (aarch64 macOS, Rust 1.97.1)

The candidate rows were regenerated after correcting per-candidate allocation scopes, exact
small-density labels, and inactive-waiter counters. They are evidence about the tested model, not
approval of an unsafe or production representation: the safety proof/tooling gaps below remain.

### H3: hydration coverage ownership

`CoverageSidecar` is a compiler-observed 16 B row. The lab compares it to (a) a sorted `u32`
absent-ordinal sidecar and (b) an absent bitmap. Both compact candidates deliberately borrow provider
routing from the canonical locality facts, so they do not silently delete the promised/missing
distinction. All 60 `{rows=0,1,4,5,100000} × {absent=0,1,50,100%}` cases produced identical
ordered coverage output.

At 100,000 rows, dense state retention is 1,600,000 B; a 0%-absent ordinal sidecar retains 0 B;
the bitmap retains 12,504 B. At 100%-absent, the ordinal sidecar is 400,000 B and the bitmap stays
12,504 B. Every representation still visits all selected rows in output order: dense and bitmap
perform one classification branch per row, while the ordinal cursor adds its present/absent cursor
comparison. Construction plus output materialization is allocator-instrumented in the raw rows,
including drop before the scope ends. This is a capacity/access trade, not a result authorizing a
production sidecar change: the real plan needs dependency-identity, iterator, and root-locality
end-to-end replay before selection.

### H5: waiter records and stale lifecycle

The dense baseline is 40 B/slot; a capacity-64 table spans 40 assumed cache lines. The new suite
uses actual `atomic_waker::AtomicWaker` fields, randomized active positions, and records logical
record visits, branch decisions, atomic operations, allocation high-water, and address-range line
estimates. Dense AoS and SoA scan all 64 records at active counts 0/1/8/64. The `u64` bitmap
candidate visits 0/1/8/64 slots respectively, but pays a bitmap atomic plus its stale-bit protocol.
The four-class byte-fit bucket also visits only ticket entries in this friendly one-credit run;
its epoch ticket is required to reject stale membership.

`bitmap_cancel_stale_snapshot_rearm` is an executable model: a snapshot bit after cancellation
sees `FREE` and does not wake the cancelled registration; rearm publishes a new active state. A
notification concurrent with rearm may be a benign spurious wake, so an admission future must
always recheck resources. That is not a linearization proof for an adoption. Intrusive list crates
were not awarded theoretical compactness: the stable-slot plus active-bitmap candidates have no
unlink/reclamation surface, while dense/SoA/buckets expose their record, branch, and cache costs.

### Flight recorder and workflow log

For deliberately non-niche test events, `Option<Event>` adds one byte: `Event68` recorder capacity
4 is 296 B vs 288 B for `ArrayVec<Event,4> + head`. At capacity 64 it is 4,432 B vs 4,368 B.
The lab models empty/one/four/64 capacity and event sizes 1/8/68/128; both ring implementations
preserve the tail `[2,3,4,5]` after six records into capacity four. A drop-spy verifies overwrite
destroys the replaced event exactly once. The shipping `WorkflowEvent` has a niche in this compiler,
so its existing four-slot recorder is 288 B already; the synthetic 68-B no-niche saving must not be
misreported as a production win.

The compact per-key log retains its `StageKey` and output once plus one 1-B accepted-kind record per
event, and differentially replays every durable prefix of the legal six-event sequence. The lab
holds rejected untrusted input in `CompactReject { event, cause }`, so a foreign-key conflict is not
erased. Its measured model retention for six reserved records is 166 B versus a 512-B ordinary
`WorkflowLog` model reservation. However, a two-key alternating six-event trace is 416 B when the
compact logs retain a global ordering vector, versus 408 B for one 68-B event vector. Therefore no
per-key durable representation is recommended absent a defined cross-key ordering/recovery contract.

### Store capacity and code size

The raw allocator and code-size files in this document predate the production static-backing split
and are retained as historical experiment evidence, not current `MemoryStore` measurements. Current
source-level allocation tests establish the replacement cliffs: `LeanMemoryStore` performs zero
metadata allocations at 0 and its exact four-entry/eight-bucket bound; heap-policy `MemoryStore`
performs two exact metadata allocations at 4 and 100,000 slots; capacity rejection performs zero
allocator activity and returns the exact owner. The 100,000-object law also records a 262,144-bucket
half-load table and a sub-64 observed probe bound. Fresh raw lab artifacts are still required before
making comparative CPU/code-size claims.

The historical release binary measurements remain a monomorphization proxy for the former
candidate model, not attribution for the current aliases. Current exact layout laws record a
104-B heap-policy `MemoryStore` and a 360-B `LeanMemoryStore` on this target. The static aliases are
therefore justified by allocator/resident-profile tradeoffs, not by an unrefreshed code-size claim.

### Unsafe ready-payload prototype and safe controls — blocked

The lab-only `PermitQueue<Payload>` uses `UnsafeCell<MaybeUninit<Payload>>`, a free bitmap and a
ready bitmap. Its written record is being repaired: claim free bit; initialize while exclusively
owned; state `READY` release then ready-bit release; consumer acquires/claims ready, reads once,
and releases. Cancellation wins `READY→CANCELLED`, drops exactly once, then releases. Retirement
must first atomically own and remove the free bit before changing `FREE→RETIRED`; the earlier order
was racy and invalidated the prototype. Epoch wrap now retires rather than wrapping, but the actual
core still requires Loom exploration, Miri strict provenance, sanitizer, concurrent differential,
ZST/over-aligned/panicking-drop/partial-init cases, and a maintained-library comparison.

The controls are safe `Mutex<VecDeque<_>>`, `ArrayQueue` at physical capacity plus one, dynamic
`thingbuf::ThingBuf`, and `StaticThingBuf`. They are measured in separate allocator scopes. For
64-B payloads, the tested eight publish/take operations request 576 B for permit slots and thingbuf,
320 B for the mutex deque, and 648 B for ArrayQueue; the static thingbuf path requests zero heap
bytes but has a 1,024-B value. This is an allocation/layout result, not a throughput result.
`thingbuf`'s queue-owned position may still lose the
stable index/epoch cancellation contract, but that is a hypothesis, not a reason to assume bespoke
unsafe is necessary. The unsafe candidate is explicitly **not** eligible for production.

### Generator control

Current upstream Colm Suite documents a Rust backend and table (`T0`), flat (`F0`), and goto (`G0`)
backends, but Nix's `ragelDev 7.0.0.12` is currently marked broken on this target. The reproducible
fallback is Ragel 6.10, which has no Rust backend; it generates C-only control programs for the
four-step cursor and a control-only workflow projection. The raw source is 2,757–4,437 B / 112–174
lines with 9–13 `cs` numeric-state mentions. The typed handwritten control is 1,898 B / 39 lines.
The old generator discards typed event variants, output equality, and exact `ReductionError` payloads;
the C-only fallback is **inconclusive**, not a source/code-size comparison with Rust. A future current
`ragel-rust` run is required before comparing generated Rust code, optimized text/data, or branches fairly. Colm's documented build also ships
Colm runtime/aapl pieces alongside Ragel, none of which may enter the portable client graph.

## Foundation semantic-scalar audit (implementation and owner handoff)

This pass distinguishes a semantic scalar from a representation-local coordinate. It does not wrap
ordinary loop variables or a malformed raw byte merely to remove `u8` from a grep result. The
implemented slice is `nudox-id`, `nudox-schema`, `nudox-frame`, and the validating use in
`nudox-view`. Root, store, hydration, workflow, observe, and runtime were read-only because their
owners were concurrently changing them.

| Area | Disposition | Evidence / reason |
|---|---|---|
| Header major/minor | implemented `ProtocolMajor` / `ProtocolMinor` | Transparent, unaligned zerocopy wire cells. They preserve an arbitrary observed byte; comparison to `FORMAT_*` is the compatibility check, not construction validity. |
| Descriptor kind/flags | implemented `SectionKindCode` / `SectionFlags` | Compatibility now accepts those exact raw cells and preserves them in `UnknownSectionKind` and `SectionCompatibilityError`. `SectionKind` remains the separately checked closed vocabulary. |
| Limit rejection operands | implemented `LimitAmount` | `LimitError::{requested,maximum}` are no longer unrelated `u32`s. The accompanying `LimitKind` supplies the byte/row/section unit. |
| Prepared-frame output length | implemented private-constructed `EncodedFrameLength` | No public `From<usize>` can forge preflight proof. Its only constructor follows the compile-time grammar bound and caller-shaped checked arena preflight; it exposes infallible conversion *out* to the native slice length. |
| Frame layout ends | reduced authoritative state | `Layout` retains only wire-width `header_bytes`, `section_count`, and typed total; descriptor/body ends are derived after preflight. `PreparedFrame` is 32 B on this target, with borrowed input slices and no inline section array. |
| Header/directory offsets and alignment | raw `usize`, intentional | These are compile-time `offset_of!` facts and native slice coordinates. They are neither persisted values nor independently constructible domain quantities; wrapping would add conversion noise at every bounds/range operation without a new proof boundary. |
| View errors for rejected bytes | raw primitive, intentional | `UnsupportedVersion`, descriptor compatibility, and malformed span errors report the *observed invalid wire byte* and process-native input coordinate. Reusing an accepted semantic type would falsely claim validity. Schema errors retain typed raw cells where they cross the compatibility boundary. |
| ID/object | already typed | `ContentRoutingWord`, `ContentId`, `ArtifactId`, `ObjectLength`, `ObjectKind`, `ProviderId`, and `ProviderSet` already name their cross-crate/persisted roles with transparent or closed types. Slice lengths in decoding errors remain native bounds evidence. |
| Root (read-only) | owner recommendation | Keep private `RowIndex(u32)` as the compact arena proof. Replace packed public-facing parent/depth facts with named 4-B `PackedParent`/`HierarchyDepth` only if the owner can retain the asserted 64-B `RootRow` layout. Replace `construction_peak_bytes`, closure capacity, and public selection work counts with distinct byte/count types; retain `usize` cursors and epoch-mark storage as representation-local. |
| Store (read-only) | owner recommendation | `ByteCapacity` and `SlotCapacity` are already correct budget boundaries. `StoreStats::{index_buckets,index_bytes,current_bytes,current_slots}` and capacity-error current counts are cross-crate accounting and should become distinct transparent count/byte scalars, with a fixed-size assertion. `StoredIndex(u32)`, bucket masks, and probe cursors stay private compact/native representations. |
| Workflow/observe (read-only) | owner recommendation | `WorkflowVersion` and closed event enums are already semantic. Keep flight-recorder `head`, `len`, and iterator positions as native ring representation state; only promote any public durable-log byte/count/work statistic, not local cursors. |

All new transparent wire wrappers have compile-time size/alignment equality with `u8`; `FrameHeader`
and `SectionDescriptor` remain 24 B and 16 B. Conversion tests prove raw major/minor preservation,
known-kind conversion, unknown-kind provenance, and the optional-extension law. Layout tests cover
arena and output-capacity N-1/N/N+1 boundaries at the actual preflight proof sites.

The frame/view negative-space matrix now combines targeted `rstest` N-1/N/N+1 policy cases for
frame bytes, descriptor count, row count, and arena bytes with a replayable raw-byte corpus. The
corpus still mutates every header and descriptor byte class, all raw kind/flag pairs, every
truncation length, payload and padding, while retaining exact typed error assertions. The direct
borrow witness test proves `ValidatedFrame` and each selected body point inside the original input;
the encoder golden and repeated prepared-frame write prove canonical bytes and reusable preflight.
No allocation or hardware-work claim is inferred from these unit tests; the scoped allocation and
logical-work evidence remains in `layout-lab`.

### Foundation API and stack hypotheses

`ContentHasher` and `ArtifactHasher` are each 1,920 B in the generated inventory. They are stack
costs at every nesting/parallel construction point, not retained IDs; profile traces must count
simultaneously live writers before changing their API. `Domain: sealed::Domain + Debug` unnecessarily
requires a formatting trait for a semantic marker. It can impose downstream generic bounds and
derived-code obligations without adding identity information; measure a bound-free owner patch and
its monomorphs before removing it. Finally, the repeated arbitrary fixed-field `write` sequences in
root, hydration, workflow, and identity writers remain a protocol-boundary hypothesis: consolidate
only if a typed preimage record retains canonical ordering, exact bytes, and error-free fixed-width
semantics. No broad writer migration is authorized from this inventory.

## Foundation const and control-flow pass

The foundation now treats a finite wire grammar as compile-time data where that removes repeated
run-time/test control flow, without importing a general unsafe flag abstraction. The design rule is
documented with qti3e's const-friendly `BitFlags` experiment (revision
`f99ee962911319cf341150e1c06c8b741c7944a7`) in
[Production Rust notes](PRODUCTION_RUST_NOTES.md#const-programming-and-closed-mutation-grammars):
sealed primitive conversions remain a last resort, not a public protocol API.

| Before | After | Evidence |
|---|---|---|
| `wire_layout_widths_are_derived_from_the_declared_field_types` was 35 cognitive-complexity points of repeated assertions. | Two declarative expected-layout tables and one compact record/field runner. | The test still compares each public width/offset to the actual zerocopy declaration and to the canonical wire position. |
| `raw_property.rs` had grown to a 575-line monolith with offset-class ladders. | Four invariant modules: fixtures, const field cases, structural mutation runner, hostile ordering/truncation. | Header and descriptor tables have contiguous full-coverage const assertions; the runner iterates each declared range directly. |

With `clippy.toml` thresholds at cognitive complexity 10 and function length 60, the isolated
four-crate gate is clean:

```sh

nix shell nixpkgs#clang -c cargo test -p nudox-id -p nudox-schema -p nudox-frame -p nudox-view
```

The raw corpus now has three separate evidence modes. Bolero combines structural-byte mutations
only; hostile ordering/truncation cases do not repeat for every fuzzer input. A deterministic
single-byte matrix performs exactly `256 × (24 header + 16 descriptor + 1 payload) = 10,496`
validator checks. The hostile suite adds 41 truncation lengths, two ordering failures, and six
correlated multi-byte limit cases (frame bytes, descriptor count, and rows at `max`/`max + 1`).
All assert exact typed errors or the exact borrowed valid section; no malformed case is silently
discarded.

## Locality artifact and rank laboratory

Production locality is now one allocation-free-to-the-library canonical artifact written into
caller storage. On the measured 64-bit target, `ValidatedLocality` is 136 B: a 16-B slice, 32-B
generation, two compact counts, and one cached 80-B `LaneTable`. Retaining that geometry is an
intentional witness cost: random reads no longer rebuild all lane endpoints, and a sequential
cursor copies the table once. The empty artifact is 48 B; measured all-overlay-absent fixtures are
216 B for 32 exceptions and 352 B for 64.

Strict big-endian exception-row validation has a scalar `TryFrom<&[u8]>` path and a reusable
root-owned `LocalityValidator` that privately caches one `fearless_simd` level. Three Apple M3 Pro
runs put the stable crossover at 32 rows: median full-artifact validation was 24,815 µs scalar vs
8,392 µs SIMD for 250,000 parses (2.96×), and 18,338 µs vs 1,801 µs at 16,384 rows (10.18× for 488
parses). Counts 0–16 stay scalar. The release fixture added 328 B of Mach-O `__text` and 16 B of
`__const`; file size was unchanged after section padding. Differential tests cover every length through
33, every alignment 0–15, every malformed short lane, long deterministic tails, exact error
priority, forced fallback/baseline, and detected execution. Raw timings and sizes are in the linked
JSONL artifact.

The former dense root-coordinate bitvector rows are retained only as
`locality_dense_exception_rank`: a contrast candidate, not a model of the production lookup. The
new `locality_production_rank` driver instead measures the actual lane grammar: sorted `u32`
exception rows for random root membership, one rank index over exception ordinals to select the
promise/overlay lane, and one rank index over overlay ordinals to select a present descriptor. Its
sequential cursor carries those ordinals without any rank query. Every candidate reports the full
artifact bytes across the sorted row, class, and overlay lanes; individual directories/tail bits;
allocator scope; random binary-search/rank work; and the zero-rank sequential assertion.

The experiment uses roots `{0,1,100000}`, exception density
`{0,1,1%,5%,25%,50%,100%}` where applicable, alternating promise/overlay class and alternating
overlay presence so both subordinate lanes are exercised. It compares prefix-per-256,
prefix-per-64, Rank9, and prefix-per-2048. These alternate rank representations remain lab-only;
none authorizes unsafe packed storage or replaces the production artifact without a separate
end-to-end win.

The older `packed_13B_route_shared_generation` and `unsafe_packed_single_owner` rows remain
contrast-only lab fixtures. Their packed unaligned loads and manual allocation owner are not used by
`nudox-root`, are not an alternative validator path, and are explicitly ineligible for production.

## Honest rubric score: 4/10 maximum at this revision

The generated inventory, raw baseline, independent store allocation control, and safe-model tests
are useful evidence. They do not clear the rubric caps: cache/branch counts are logical
instrumentation rather than hardware counters; the
unsafe queue has no actual-core Loom/Miri/sanitizer/concurrent differential proof; code-size does not

## Tooling and evidence gaps

Available now: stable layout primitives, generated Rust inventory, explicit LLVM debug discovery,
Clang through `nix shell nixpkgs#clang`, and a matching nightly Miri through
`sh layout-lab/run-miri-foundation.sh`. The direct host shell lacks Clang, hence the Nix shell in
ordinary scripts. `perf`, Valgrind, Instruments/xctrace, `cargo-bloat`, and `cargo-llvm-lines` were
unavailable at audit start. macOS `leaks` exists but has not yet produced a scoped reproducible run.
The first allocator-count experiment uses a reviewed test-only facility or external profiler; a
handwritten global allocator is intentionally not introduced merely for a number.

The matching nightly now passes Miri for the frame preflight/write and validated view boundaries;
the exact command, target, isolation setting, and results are in
[miri-foundation-aarch64-apple-darwin.txt](layout-lab/raw/miri-foundation-aarch64-apple-darwin.txt).
Bolero requires `-Zmiri-disable-isolation` only because corpus discovery uses `stat`; all view
property cases still run under Miri. The earlier permit-queue attempt remains recorded in
[miri-aarch64-apple-darwin.txt](layout-lab/raw/miri-aarch64-apple-darwin.txt), but is not a
foundation result. Address/thread sanitizer is likewise unavailable without a compatible nightly; see
[sanitizer-aarch64-apple-darwin.txt](layout-lab/raw/sanitizer-aarch64-apple-darwin.txt). Neither
failure is safety evidence.

An unsafe candidate remains out of production until its record includes the safe-reference deficit,
validity/initialization/bounds/alignment/provenance/aliasing/lifetime/drop/cancellation proof,
differential and fuzz results, Miri and sanitizer output, applicable Loom evidence, assembly/layout
evidence, an end-to-end win, library comparison, safe public surface, and rollback plan.
