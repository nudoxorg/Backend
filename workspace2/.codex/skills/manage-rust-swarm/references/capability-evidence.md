# Capability working artifacts

Use this reference only when a capability needs durable multi-agent artifacts. Evidence describes
technical work; it never authorizes implementation.

```text
.codex/evidence/capabilities/<capability-id>/
|-- brief.md       # compact Sol manager packet
|-- rubric.md      # living executable rows
|-- research.md    # decisions changed, controls, saturation
|-- insights.md    # recurring agent/process observations
`-- closure.md     # final candidate and raw evidence
```

Keep each file canonical and update it in place. Git retains earlier versions. Do not create packet
subtrees, pre-edit reviews, amendment chains, digest rebinding commits, dispatch receipts, or a state
machine whose purpose is permitting code changes.

## Binding

The brief names the baseline commit/worktree, public terminal, owned paths, laws, negative space,
chief red, and return condition. The rubric binds each row to an exact command/artifact and mutant.
Research rows name the decision and code/test changed. Insights follow `AGENT_LEARNING.md`. Closure
names the candidate commit, final rubric states, review, raw gates, and uncertainty.

Worker provenance is the task ID, model/role when available, baseline, commit, paths, and commands.
Missing runtime metadata never invalidates reproducible code. Rejected variants remain addressable by
commit until Terra records which invariant/test/algorithm was absorbed or why a counterexample
rejected it.

`PRODUCT_BLOCKED` requires a reproducible product, authority, external-system, or toolchain failure
after two materially different technical attempts and an external resolution owner. Missing agents,
reviewers, model routes, capacity, sandbox telemetry, or evidence formatting are process incidents;
Terra or Sol continues directly.
