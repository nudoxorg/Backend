## The defect (manager-verified against gopkg.in/yaml.v3@v3.0.1)

`satisfactions()` decides locality with
`row.target_package.is_empty() || row.target_package == self.package`
and then resolves the target in the SUBJECT declaration's package. But
a satisfaction edge's target lives in the TARGET's package: with
`Tests: true`, the oracle loads external `_test` packages, whose types
satisfy interfaces declared in the module's primary package (observed:
a `gopkg.in/yaml.v3_test` type satisfying `yaml.Marshaler` — target
package `gopkg.in/yaml.v3`, subject package `..._test`). The projector
treats the row as local (target package == primary) but looks the name
up in the SUBJECT's package, misses, and faults
`ProjectionFault::SatisfactionUnresolved`.

The producer's law makes the target ALWAYS module-local:
`collectInterfaceCandidates` only gathers interfaces declared in loaded
module packages, so `target.Pkg` is always a package this image carries
declarations for. The foreign-key arm exists for robustness only.

## Required repair

In `satisfactions()`, resolve the target in the TARGET's declaring
package: use `row.target_package` when non-empty, else the subject
declaration's package (the producer leaves it empty only when the
target declares in the subject's own package). Look the name up via
`self.lookup(package, row.target)`; on a hit, project the local
ordinal; on a miss ONLY, fall back to the existing foreign `go`
lineage key. The `SatisfactionUnresolved` fault loses its reason to
exist on this path — remove the variant if (and only if) no other site
raises it, and note the removal in the commit body; otherwise leave it
untouched.

## Required falsifier (new test in mod tests)

Extend the Fixture with a TWO-package image: package `demo` declares
