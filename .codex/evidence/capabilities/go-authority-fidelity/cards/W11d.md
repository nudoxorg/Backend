## The defect (manager-verified against golang.org/x/sync@v0.10.0)

`validate_references` (image.rs:1936-1949) rejects a reference row when

```
row.file > previous_file
    || (row.file == previous_file && row.span.0 < previous_start)
```

The first disjunct is INVERTED: ascending file order (byte-slice greater
than the previous file) is exactly the canonical direction, but it is
rejected as out of order. Every multi-file module faults at the first
reference whose file sorts after the previous row's file (observed:
`Go authority reference 2 is out of canonical (file, start) order` on
x/sync — errgroup.go refs followed by go120.go refs). Single-file
fixtures never tripped the inverted arm, so the battery stayed green.

The correct law: rows must be non-decreasing by (file bytes, start):
reject when `row.file < previous_file`, or when the files are equal and
`row.span.0 < previous_start` (equal keys are legal — the producer
sorts by (file, start, owner, target)).
