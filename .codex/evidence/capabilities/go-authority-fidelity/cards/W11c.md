## The defect (manager-verified against golang.org/x/sync@v0.10.0)

`buildAuthorityPlan` resolves every reference owner as
`local[reference.Owner]` BEFORE consulting `OwnerRecv`. `local` maps
PACKAGE-LEVEL declaration names only; a reference from inside a method
carries `Owner` = method name (e.g. "SetLimit") and `OwnerRecv` =
receiver type name ("Group"), so the first lookup faults with
`go/types emitted a reference from undeclared owner "SetLimit"` — every
real module with a method that calls anything fails authority-image
generation. The receiver branch at image.go:1093 is dead code today for
exactly the case it was written for.

## Required repair

When `reference.OwnerRecv != ""`, resolve the owner row through the
RECEIVER declaration: `owner = local[reference.OwnerRecv]`; the bare
`local[Owner]` lookup applies only to free functions (empty
`OwnerRecv`). Preserve the typed-fault law exactly:

- empty `OwnerRecv` + unknown owner name -> the existing
  "undeclared owner" fault retaining the name;
- non-empty `OwnerRecv` + unknown receiver name -> the existing
  "undeclared receiver" fault retaining the name;
- non-empty `OwnerRecv` whose receiver IS declared -> owner resolves to
  the receiver declaration row; no fault.

The wire format, digest domain, and row geometry are UNCHANGED — this
is plan construction only.
