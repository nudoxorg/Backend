## Public terminal

The Go lane renders docs.rs-style goldens through the existing
`compiler/ir` render displays (`SignatureDisplay`, `TypeDisplay`,
`DocsDisplay` — read `compiler/ir/render.rs` and the sibling
`compiler/driver/tests/python_render.rs` as the calibrated template):
a real Go module compiled end-to-end (oracle image ->
`compile_ir` -> `Ir`) renders exact pinned text for its structs,
interfaces, functions, and methods, and mutating one field or doc in
the fixture CHANGES the pinned text.

## Fixture (checked into the test as source text, materialized at runtime)

One Go module written to a fresh temp dir (`go.mod` + one .go file,
std-only imports so no network is needed), exercising:

- a documented struct with typed fields (incl. a field with a struct
  tag and an embedded struct),
- an interface with an explicit method plus an embedded interface,
- a generic function and a generic type (`[T any]`, two params with a
  constraint),
- a value-receiver and a pointer-receiver method,
- a const group with iota,
- a package doc comment and per-declaration doc comments.

## Required proof shape (mirror python_render.rs)

1. Run `GoOracle::authority_image(source_path, module_dir)` (the crate
   is already a regular dependency of compiler-driver:
   `compiler_languages_go::GoOracle`); check its `.run` handshake only
   if needed for schema pinning.
2. `compile_ir` with `SemanticAuthorityInput::Go { image: &image }`,
   profile `LanguageProfile::Go(GoVersion::Go125)`, source = the same
   file's bytes (the image digest-binds them).
3. Locate entities by exact name; render each through the displays;
   assert EXACT strings (golden table in the test, not a snapshot
   file) for at least: the struct item's signature/type display, one
   field type, the interface method set surface the lane exposes, the
   generic function's signature, one method with receiver, one doc
   body, and one constant.
4. Mutation falsifiers (each runs the whole path again and must
   produce a DIFFERENT pinned string): change one field's type; change
   one doc comment. A flat name-only rendering fails these.
5. Typed-unavailable: if the toolchain cannot spawn, the test must FAIL
   with a typed error naming the toolchain — never return Ok (the
   brief's failure mode; python_render's `MissingPython` is the
   precedent).
