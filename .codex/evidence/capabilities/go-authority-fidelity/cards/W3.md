## Rows

### R1 — Parameter-name facts (M3)

The v5 `signature_parameters` plane (reader:
`GoImage::signature_parameter(s)`; row = owner func-type-row index,
ordinal, name atom, offset) must feed every parameter and result carrier
fact of every executable row — package functions, methods, interface
methods. Carriers keep `EntityKind::Parameter`; their names become the
exact image names. A blank image name projects as `_`. The variadic bit
stays on `GoSignature`. Falsifier: build the fixture image for
`func F(a int, b string) (c error, d ...int)` plus one method with a
receiver; decode; assert carrier names `a, b | c, d` in order for F, the
same for the method's own parameters, and variadic still set on `d`'s
signature. Also assert a `_`-named parameter projects as `_` (not
fabricated).

### R2 — Self-nominal and mutual recursion (M4)

Falsifiers: `type L struct { next *L }` and `type A struct { b B }` with
`type B struct { a *A }`; decode type facts; assert `L`, `A`, `B` project
Nominal records resolving to their own ordinals (diagonal self-nominal
and mutual reference), with zero typed-Unknown rows. The pass-one
backward-anchor mechanism already claims this; the corpus tests never
exercised mutual recursion — add them.

### R3 — Per-declaration package resolution (M5)

`Projector::new` takes `image.declaration(0).package` as THE local
package and `names` is image-global: a reference inside a non-first
package with an empty `target_package` orphans. Reproduce this red first
(the two-package fixture faulting OrphanTarget), then repair: names and
occurrence/satisfaction resolution key on the OWNING declaration's
package (declaration rows carry `.package`; reference and satisfaction
rows carry their owner's context). Falsifier after repair: two-package
image (a first, b second): b's function calls b's helper (empty
target package) → Local occurrence to b's helper ordinal; b's satisfaction
edge targeting b's interface → Local; a cross-package reference
(`target_package` set) → Foreign go lineage as today.

### R4 — Interface method-set plane

The v5 `method_sets` plane carries one interface's complete
post-embedding method set: rows (owner type-row, name, sig root or none,
package atom). Laws:

- Entries whose package equals the owning interface's package project as
  Function facts (through the existing `executable` path, deduplicated
  against the members the explicit interface-member run already pushed)
  and attach to the interface fact's `GoFacts.method_set`.
- Entries whose package differs stay image-only: no local Function fact
  is fabricated for a declaration the module does not own. Document this
  classification in the module header.
- Falsifier: fixture with interface I embedding local J (I's set is the
  deduplicated union; the J method's ordinal is shared, not re-pushed)
  and I2 embedding `error` (no local fact named `Error` fabricated;
  I2's set carries only its own explicit locals).

### R5 — Package rows as Module entities

Every v5 package row (`GoImage::package(s)`: import path, clause name,
files) projects exactly one `EntityKind::Module` fact named by the import
path. Package-level doc rows (`DocOwner::Package`) attach to that
package's Module fact instead of being skipped, resolving the doc skip in
today's `docs()`. The declaration→package association must remain
recoverable from the fragment (worker chooses within the existing lane
surface — fact children or ordering laws — without compiler/ir edits);
the choice is asserted by a test. Module-row metadata (go directive,
resolved version) has no lane cell and stays image-only — documented, not
dropped silently.

### R6 — Honest header

The module doc header's v4-era text ("Image rows carry no parameter-name
plane … carrier facts use Go's blank identifier") is rewritten to the
post-card reality, including the exact image-only list: foreign
method-set entries, module metadata, constant values (escalation M6
pending), receiver spellings.
