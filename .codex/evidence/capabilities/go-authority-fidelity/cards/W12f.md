## The defect (manager-verified: gopkg.in/yaml.v3@v3.0.1)

`extractReferences` walks every `*ast.FuncDecl` with a body — including
`func init()`. `referenceOwner` resolves init to a `*types.Func`
successfully (no receiver), so a call inside an init body is emitted as
`Reference{Owner: "init"}`. But `init` is an implicit function: it never
becomes a declaration row in `buildAuthorityPlan`'s `local` map, so
image generation faults:
`go/types emitted a reference from undeclared owner "init"`. Every
module whose package has an init() that calls anything fails
authority-image generation.

## Required repair (representation law, manager-decided)

An init body is anonymous — there is no declaration entity to anchor
the reference, and synthesizing one would invent a public entity for an
implicit function. So `extractReferences` must SKIP reference
emission from init functions at the walk: when `fn.Recv == nil &&
fn.Name.Name == "init"`, do not walk that body. Document the exclusion
with a comment stating the law (implicit functions have no declaration
row; their call edges are not representable as reference rows and are
deliberately not recorded). The wire format is unchanged.
