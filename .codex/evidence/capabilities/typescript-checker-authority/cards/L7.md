## Public terminal (matrix rows R8 + R9 + the package-class integration law)

Twenty mostly-random REAL npm packages — including lodash, zod, and
@types/react, plus >= 15 niche packages spanning: a scoped package, a
monorepo subpackage, a package whose types are BUILD ARTIFACTS (npm build
leg proven), a package using typesVersions or a non-standard layout, and
plain single-package .d.ts shippers — travel PURL -> locate -> fetch ->

## Required behavior

1. **Corpus table.** A declarative in-test table of exactly 20 rows:
   purl, package class (enum: SingleShipped, Scoped, MonorepoSubpackage,
   BuildArtifacts, NonStandardLayout), entry expectations. Every row runs
   the full lifecycle. Network unavailability after one retry is a typed
   error receipt, never a skip.
2. **Package-class codification (integration law).** For EACH class, one
   dedicated focused test codifying the class's packaging contract
   (location rule, entry-resolution rule, lockfile fact, build-leg rule) —
   the class tests use one representative package each and assert the
   CLASS's invariants, not just the package's.
3. **Deep fidelity verdicts.** Per package, the receipt records:
   exported-declaration census (declarations the source/`.d.ts` exports —
   derived by reading the package's entry sources in the receipt builder —
   vs declarations present in the decoded IR); sampled computed cells
   (>= 10 or all exports if fewer) with the checker's own printed type
   beside each; 2+ render-truth samples with expected text; every
   `TypeTree::Other`/TypeReason fallback row attributed with the exact
   source construct that caused it; occurrence-origin spot checks.
   Verdict per rubric.md (dimensions 1-6, blockers B1-B5), totals in a
   committed table. You do NOT score generously: an unexplained fallback
   you cannot justify against source truth is a 0 for that dimension and a
   defect-class row.
4. **Perf profile (R9).** Per package: machine-readable (JSON) lowering
   time split parse/check/lower, wall clock end-to-end, decoded fact count.
   First run freezes the baseline numbers in receipts/L7/perf-baseline.json
   with the machine metadata; the harness has a stated regression cap
   constant (name it, justify it) for later runs.
5. **Mutation sensitivity.** One committed mutation check: flipping one
   lowering rule (e.g. in the test, corrupt one report fact before
   injection with digest recomputed) must flip >= 1 verdict in a focused
   test proving the verdicts are load-bearing.
6. **Old-fragment law.** Every lifecycle run keeps the schema-1 golden
   transcript decode assertion green beside it (one assertion in the
   driver is enough; the transcript bytes are pinned already).

## Bounds and stop decisions

- 20/20 rows must RUN. A package that cannot locate/lower after TWO
  materially different support attempts stays in the table as FAILED with
  the defect class and the raw error — a gap, never a delisted row.
- No production edits, no support-module forks, no per-package special
  cases outside the declarative table + class enum.
- Caps/deadlines: reuse L4c-r1's support constants; any new constant is
  named with its justification.
- Worker-turn budget: land the driver + class tests + receipts for the
  first 10 packages as checkpoint 1, all 20 + perf + verdict table as
  checkpoint 2. If one package's defect needs > 30 lines of support
  workaround, stop that workaround and record the defect instead.

class list (each with one example package + raw evidence), and the
