# Startup reporter descriptor and cleanup follow-up

This follow-up closes a separate pathname race found during review of the startup receipt channel. The earlier reporter checked the pending record by path and then published with `write_private_atomic`; `StartupAttempt::drop` could remove the old entry between those operations, allowing the writer to recreate a status path after its attempt ended.

The reporter now opens the pre-created private file once with no create flag, holds that admitted descriptor, and takes an exclusive file lock while checking the exact pending bytes and appending a bounded terminal frame. The root reader admits a private descriptor, confirms its file identity matches the attempt's held file, takes a shared lock, and only accepts a complete, canonical, bounded terminal record. An incomplete frame, replacement, or second report cannot become a reported cause.

The attempt now creates its initial pending file exclusively beneath a validated private directory and retains that file descriptor plus the pinned directory capability. On drop it locks the original descriptor, reopens the named child through the capability with the existing private-file checks, and removes it only if the named object still has the original identity. The replacement test verifies both identity and bytes remain unchanged after dropping the attempt. On Unix the final unlink remains name-based; the identity check relies on the existing owner-only private-parent namespace boundary and does not claim atomic exclusion of a same-user rename in the final syscall window.
