# Experimental shared SQL contract

The unadmitted `call_worker` path is a research convenience. It must not be used as a product authority. Its SHA-256 is framing evidence, not a workspace source identity or graph key. Native grammar, scope and catalogs remain adapter-specific; lexical IDENT-token coverage is never a declaration/reference list.

The separate `analyze_checked` path requires the caller's authenticated `InputContentVersion` and `ContentId<SourceFactDomain>`, actual host bytes, and an already admitted `ToolchainArtifact`. It uses `VerifiedSourceText::admit` for both domains, requires the request bytes to match that host, and validates each returned coordinate with `VerifiedSourceText::extent`. It launches through the existing `ProcessSupervisor` with explicit empty environment, caller limits and cancellation; only a successful reaped receipt is decoded. Its returned command identity commits the execution inputs and environment. This API does not authenticate workspace membership, a proposed catalog, build provenance, or the caller's artifact admission.

Protocol v2 requires a finite expected producer recipe and rejects unknown fields. The supported pgrust recipe records revision, embedded standalone lock hash and the actual default scanner settings (backslash_quote=2, escape warnings=true, standard strings=true, server/client encoding=0, SQL_ASCII). The supported syntaqlite recipe records revision, embedded lock hash, version=2147483647 (Latest sentinel), cflags=0 and its analyzer's default DQS fallback. This describes the native analyzer, not a SQLite connection's DQS setting. Any other requested values are UnsupportedSettings. These are narrowly observed one-shot defaults, not a complete PostgreSQL session or SQLite connection identity; no durable configuration root or build attestation exists.

Both native contexts remain caller-proposed and noncanonical: SQLite returns partial diagnostic evidence for one SELECT, PostgreSQL partial context-local read witnesses for a restricted SELECT. No absence, complete binding, persistent object identity, AUX/cursor, product indexing, CLI or MCP support follows. Exact effective native settings beyond the recorded subset, parser depth/memory bounds, portable native source packaging and installation admission remain release gates. Generic tree-sitter infrastructure appears transitively through backend-compile, but neither SQL adapter uses it as a parser or fallback.

The original f30 receipt is historical; its exact receipt and matching logs are preserved separately under `results/sql-facade-f30-*`. The checked-runtime receipt is `checked-receipt.json` in this directory.
