# Experimental SQLite native adapter

Pinned upstream syntaqlite `4e4de76312429fb2235ae093ab2125914320d5bd`, version 0.13.5, Apache-2.0. It uses SQLite-derived C grammar/tokenizer with Rust bindings; this is not a PostgreSQL parser. Its path checkout is an external research dependency, so this package remains nonportable and is excluded from the product workspace. The compile uses SQLite, fmt and analysis features: SQLite alone failed in this revision because upstream imports fmt-gated modules.

The shared SQL contract includes dialect, engine revision, source digest and honest parse/binding coverage. The SQLite adapter supplies native parse results and MissingContext, with lexical identifiers explicitly unavailable. A one-shot worker uses the shared process framing. A separate test exercises the actual native analyzer with a declared synthetic catalog and validates an unknown column diagnostic; this is not wired to product binding. The checked path records syntaqlite version/cflags and analyzer DQS behavior and uses the existing supervisor and source verifier; canonical catalog identity and installation admission remain open. No database, SQL execution or migration is involved.

The worker also accepts an adapter-specific `ProposedCatalog` (sorted tables and column names, explicit epoch, bounded canonical JSON); the result carries its digest and native diagnostic kinds/byte extents. This is caller-proposed context, not admitted catalog identity or complete binding evidence. The fixture always supplies a known column list; syntaqlite conservatively accepts unknown columns when a list is absent, so absence of diagnostics is never presented as an exact reference or complete graph. SQLite's default double-quoted-string fallback is demonstrated separately from PostgreSQL. This profile has no custom functions, extensions, attached databases, or dynamic dialects; the recorded analyzer settings are not a durable workspace configuration root or a claim about any real SQLite connection.

## Syntactic outline (protocol v4)

For every file that parses, the worker returns `Response.outline`: one `StatementOutline` per statement, built from syntaqlite's typed AST and token stream (`src/outline.rs`, which documents the conventions). It is produced with or without a `context`, for multi-statement files and for non-SELECT statements; a parse error gives `Syntax::NativeError` and no outline. The single-SELECT `ProposedAnalysis` binding is unchanged. The worker validates its own outline with `Outline::validate` and refuses to answer (`Syntax::Rejected`) rather than report one that fails.

What it contains: definitions (tables, views, indexes, triggers, columns, with `Create`/`Drop`/`Rename`/`AddColumn`/`DropColumn`, `IF [NOT] EXISTS` as `conditional`, and the declared type text of a column in `detail`); references (relations, columns, functions, indexes, triggers) with `Read`/`Write`/`Schema` roles and byte extents of the written spelling; and scope entries (FROM items, joins, CTEs, derived tables, table-valued functions, DML targets, `excluded`, trigger `new`/`old`) with the region in which each name is visible. Names are ASCII-lowercased with quotes removed and escapes undone. Nothing is bound to a table: `a.b` gives qualifier `a`, a bare `b` gives none, and the owner resolves across files. Where the syntax ties a column to one table (key lists, foreign keys, INSERT column lists, UPDATE SET targets) the qualifier is filled in.

Known gaps, each reported as `Partial`:
- `CREATE VIRTUAL TABLE`: the table is defined; its module arguments and columns are not (`UnmodeledConstruct`).
- `CREATE TABLE ... AS SELECT`: the SELECT is walked, but the new table's columns are not listed (`UnmodeledConstruct`).
- `ATTACH`, `DETACH`, `EXPLAIN`: not modelled (`UnmodeledStatement`). Attached schema names are not defined.
- `PRAGMA` with an object argument (`table_info`, `index_list`, ...) and `ANALYZE`/`REINDEX <name>`: the named object is not extracted (`UnmodeledConstruct`).
- Item, statement and name-length limits of the contract (`Limit`); nesting deeper than 192 levels stops descending.
- Not extracted, and not flagged because they are not references in this model: `COLLATE` names, `CAST` type names, window names, and the result-column names of views, CTEs and derived tables.
- Implicit `rowid`/`oid`/`_rowid_` columns appear as ordinary unresolved column references; a bare double-quoted name is emitted as a column reference (SQLite falls back to a string when no column matches) and the owner decides from the `"`-prefixed spelling.
- The `excluded` region and a few other list-item regions can run a little past the construct they name (the parser's node extents start list items at the head of the list); regions are always inside the statement.
