# Python packaging usefulness repair

Original source baseline: canonical `6ac9f5438b`; current reviewed successor: canonical `8c527f379b`. This change uses one static extraction path for local package identity/dependencies/residence and forge manifests. It does not execute or import setup.py, attribute modules, build hooks, or package code.

The portable `PythonProjectMetadata` contract records literal declarations, dynamic declarations, or omitted fields independently, with relative source paths, exact byte lengths and BLAKE3 digests. Provider publication authority and native compiler capability remain separate. Local package profiles and forge detail/acquisition payloads expose this typed metadata; readable CLI/MCP projections expose description, documentation/repository URLs, interpreter constraints, dependency declaration counts and unavailable reasons.

The extraction supports PEP 621 project metadata, INI setup.cfg (including extras, build/test declarations and comparator commas), and a bounded Ruff-parsed straight-line literal setup.py subset. `attr: package.__version__` is resolved only from one unambiguous in-root module or package initializer containing safe literal statements. Computed expressions, control flow, duplicate bindings, arbitrary executable statements, unsupported cfg/setup dependency overrides and dynamic PEP 621 fields remain explicitly incomplete. Unix filesystem reads use root-directory descriptors and NOFOLLOW for each component; escaping or symlinked metadata sources are rejected. Supporting attribute-source changes and newly appearing attribute candidates invalidate local cached metadata/dependencies. A per-refresh typed read cache shares one extraction outcome across identity, input hashing and dependency adapters; malformed roots keep their own cached error while other roots retain their facts.

The local profile repair also fixes exact-path identity lookup: an indexed local root's manifest PURL must not be discarded merely because the request used a Local path operand. Dynamic Python identity returns available source declarations and an unavailable version instead of inventing a package release. Mixed Python/JS roots preserve existing manifest identity precedence; Python declarations are displayed separately.
