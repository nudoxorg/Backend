## Transport and freshness redesign

The old observer uses 1 s socket deadlines and three reconnect attempts. The producer's unchanged-cursor subscription returns immediately by design, but an owner step may delay control processing. The listener permits an admitted reply to wait far longer. The old framed reader loses partial header/body progress on timeout, so simply catching `WouldBlock` and reading again is invalid; repeated disconnect/retry can leave admitted server workers waiting.

The reviewed design uses one exclusive borrowed in-flight exchange with bounded encoded request/write offset, partial frame-header/body offsets, exact request correlation and existing mailbox limits. Short OS deadlines drive cancellation/freshness ticks without re-sending a request or restarting a frame. Overall stall, peer closure, cancellation and protocol invalidity remain distinct. Dropping an incomplete exchange poisons that stream before another request can use it. No detached reader or new wire protocol is introduced.

The first shared transport implementation is frozen source-only at `7579a85bf530b1d388e8a323c142d0a01876acf9`; root has reviewed its full changed production/test source, while Cargo gates remain pending. A follow-up will separate the exchange state machine into a focused private module and carry one typed observed control through the existing publication admission loop. The desktop suspension seam `9a3aea497…` has been reviewed separately: it revokes read attachment readiness while keeping the last complete display root and the one active observer socket token. Only certified complete publication re-admits a new attachment. Its observer call site remains unwired; it is not a deployed liveness fix.

An authenticated reset already has a fixed aggregate `PublicationBudget`: 10 s plus 2 s per required 64-row page, capped at 131072 rows and 2048 pages. A new per-frame exchange budget must preserve that outer deadline rather than truncate valid large resets or restart the clock for each page. Ordinary stale-read and recovery timing needs real blocked-owner measurements; GUI startup latency is not subscription latency. Control-plane scheduling and abandoned-ticket cleanup remain producer work. Tests must cover partial writes/reads, exact single admission, quiet waits, false readiness, certified recovery, lease rejection versus local proof invalidity, EOF/reset, shutdown, and bounded worker reclamation.
