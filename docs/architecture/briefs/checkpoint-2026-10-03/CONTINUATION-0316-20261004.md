## Architecture decisions to retain

The `c008` typed structural row-tree foundation is not yet the persisted producer format. Current cluster staging still uses ordinal NXFI byte chunks; a segment planner alone cannot make those strongly edit-local. Compatibility readers and full-image validation remain necessary until the producer and transport cut over coherently.

The next IR step reuses the existing canonical plane encoder and row visitation, rather than introducing another IR. One sink can preserve current SPIR output while another emits content-addressed rows and typed manifests. Publication must bind exact semantic build identity, image facts, input claim coverage, catalog root, and all family closures. A catalog root alone is not complete semantic provenance. Full planning/sorting and tree construction are currently proportional to rows; path-copy and incremental producer claims require an exact complete delta and positive/negative dependency witnesses. Missing toolchain/environment/read observations must disable reuse, not manufacture purity. The shared row-visitor slice was frozen before edits, at `1faaab9`; it has no implementation commit.

Discovery storage should reuse the existing `backend_version` canonical relation and persistent tree as **one typed, authenticated metadata row map**, with encoded-byte-aware chunking. It should not maintain a duplicated whole fact blob plus directory, or call an XOR accumulator an authenticated Merkle map. Typed fixed keys, closed section/row values, immutable manifests and coordinate dictionaries allow rows and tree nodes to share across versions. Catalog roots map coordinates to immutable fact versions. Bulk SQL current-head/core reads serve search; pinned immutable roots serve historical details.

That design is not implemented by this checkpoint. Required work includes the async Turso/tree-loader seam, one coherent fact-version identity formula, row and aggregate heap bounds before cloning, exact transaction ownership across objects/heads/history/receipts/outbox, explicit durable pins/pruning/tombstones, cold root verification before projection ACK, and independent golden/fault/reopen tests.
