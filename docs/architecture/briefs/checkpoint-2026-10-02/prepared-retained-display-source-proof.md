# Prepared retained display: source proof and pending gates

The model owns only the raw serde/projection vocabulary `RetainedDisplayWire`. It carries historical claims, not admission. Closed-display consumers import the type directly from runtime::snapshot; the model does not re-export or depend upward on that runtime type. The closed runtime `snapshot::admitted::RetainedDisplay` has private fields and a constructor visible only to the snapshot module and its capture/decode children. Those background paths validate full address/source scope, shape, budgets and content digest once. After admission, matching compares the original exact typed Route, without hashing source/README bytes or scanning display rows. GUI code borrows metadata/body or shares a prepared source Arc; it cannot construct a closed display or deserialize one directly. A closed display remains `served() == false` and never seeds a current Resource or owner action lease.

Source and README preparation shares the wire's Arc text, constructs SourceText once, and prepares direct line offsets off-thread. Existing SourceText checkpoints rescan the full span of a long minified line; simply retaining its sparse index would leave that paint cost. The optional saved-display index stores ByteSpan's two u32 offsets (8 bytes per line), with an explicit 8 MiB final retained-offset allocation budget including Arc headers, alongside the bounded 2 MiB shared text. Construction first builds a bounded Vec and converts it to Arc; that conversion may temporarily hold both offset allocations, as well as the previous sparse checkpoints. The final retained budget is not a claim that preparation peak allocation stays within 8 MiB. The budget check rejects oversized line counts before building that Vec. The direct index replaces sparse checkpoint allocation for the final retained display. Ordinary current-source construction remains sparse. Excessively line-dense display caches become unavailable instead of allocating an unbounded offset array. Checked one-based range and overflow semantics remain in SourceText construction. Display excerpts must match both the body's first line and the prepared source's full line extent.

The same prepared SourceText feeds existing bounded SourcePage/history calculations on repaint. A test-only scan probe demonstrates that an ordinary 1 MiB minified line exercises a full sparse scan, while 64 pages through prepared offsets do no sparse byte scanning; pages still obey existing byte/line bounds. Direct offsets and text are shared, with no duplicate content strings. A background-calculated body/observation discriminator partitions per-route/per-window local pager memory; it supplies no semantic permission.

Readings mount at most 32 rows at a time. Worker admission caps each row/title at 4 KiB and the full projection at the existing word/row budgets. Local Previous/Next buttons reuse the existing native FACET control, target registry and Reader's per-route pager memory. Source/row callbacks recheck exact mounted visit and exact closed display, then the expected cursor. Another route, owner-independent live Resource arrival or replaced display cannot inherit an old callback's local memory. Back restores only its own route's pager. Populated Resources, including refused wrong-shaped values, continue to block cache fallback; the selector does not rehash their bytes merely to establish that they exist.

Quit before destination preparation now preserves the previous private last-route file instead of writing an empty file or unrelated support sections over it. This leaves the old file's original exact-scope claims intact; it does not relabel an earlier observation as newly current. Existing completed legacy saves and worker-prepared display saves retain their behavior.

Source regressions cover forged wire digest/binding rejection; prepared text/index Arc sharing; excerpt and first-line overflow gates; excessive direct-index allocation refusal; the minified sparse-vs-prepared scan oracle; actual Reader repaint sharing, native AccessKit/pointer pagination and stale source callbacks; bounded native reading rows, per-visit/Back memory; and preservation of previous private cache bytes when quit has no prepared destination. All are pending compilation/execution.

Validation is rustfmt parsing and whitespace checks only. No Cargo, native test execution, CUA, live owner, cold application restart, paint timing or full width/text/theme matrix has run in this isolated follow-up. Archived operation worktrees remain frozen and unchanged. Runtime/GUI gates await root composition and explicit authorization.
