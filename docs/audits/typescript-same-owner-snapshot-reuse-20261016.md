# Native TypeScript same-owner selected-output reuse

Source parent: `174671aaa656c37e1e48518973a909c9de1b3b87`. This is a source-only implementation. Native compilation, regression execution, product indexing and elapsed/RSS measurement are **UNRUN**. No Report26 recovery or measured speedup is claimed.

An unchanged `add . --wait` previously re-entered TypeScript package compilation because `compiler_input_admissions` deliberately assigns non-Python profiles `ReadSetCompleteness::Unproven`. The scanner's source/config digest cannot prove compiler dependencies or negative resolution candidates. `--wait` only controls the caller's observation lifetime. Canonical already retains a TSZ checked image within each compiler lane, but fresh host/forest admission and semantic projection still run; cold owners lose that image.

The direct native TSZ adapter already routes its filesystem reads through the captured resolver. Its owned forest witness replays positive file bytes/identity/length, missing paths and nearest parents, external negative module parents and peer directories, exact directory entries, and realpaths. Native host validation re-admits config discovery, selected build configs and workspace authority. The checked-program environment binds linked TSZ authority, host fingerprint, resolver digest, native options, source and embedded-library content, diagnostics, exact module outcomes and file formats. Configuration inheritance, project references and package exports/type-resolution inputs enter through this same filesystem adapter. No Node or alternative compiler is introduced.

This slice retains one bounded native host/forest witness in the current compiler owner, after actual local staged output has been selected. Registration requires the selected binding to equal that staged output's binding. Lookup requires the same owner, canonical root, profile, scanner source/configuration tuple and selected binding, followed by replay of the original witness. The scanner digest is an additional equality key; it never replaces that replay. Sorted source tuples give identical keys when unchanged source rows move from fresh handles into reused scan rows, without dropping duplicate tuples.

Only a single live TypeScript profile with no lost profile can take this shortcut. Mixed profiles, absent/evicted witnesses, Compiler API fixtures, cold owners, changed bindings, changed observations, cancellation and dead owners fall back to compilation. Only `TypeScriptSourceExcludedFromConfiguredProgram` gaps may be retained: configured exclusions preserve honest partial scope. Work-budget/deadline gaps, authority/native refusals, representation gaps and all other missing semantic authority force another compile so Add remains a retry surface. Activated-runtime `StagedEmbeddingStatus::Unavailable` also prevents reuse, permitting inference retry. `NotConfigured`, `Available` and owner-frozen `ProvisioningUnavailable` remain eligible. A newly selected output retires its prior root/profile proof even if the replacement is ineligible. This does not construct a `Complete` admission or upgrade semantic coverage.

The opaque proof is attached to the existing source revision fence. Its original dependency replay therefore runs again through the existing final product-selection barrier, including the synchronous source route. A dependency edit after the initial cache lookup can reject final admission. Staged native solver/checker state is not serialized. Durable semantic images remain the existing selected output; the retained proof only establishes when that exact output may remain selected.

Retention is one cache slot, capped at 64 MiB of conservative host/forest accounting, including captured source bytes, duplicate path payloads, tree/directory metadata, forest Vec capacity, transcript Box slice objects, every retained String/Vec capacity and nested matcher JSON allocation. Compiler API transcripts also have independent serialized-report/count bounds (including the 8 MiB report allowance); these limits are separate from retained-memory accounting. The direct native producer currently has empty compiler_accesses/directory_views, but the shared witness accounting still charges these owned fields. Source review caught their omission before merge; this is an accounting correction, not an observed native overrun or production failure. Outstanding revision fences share their exact proof and can temporarily retain an evicted predecessor. Native peak/idle RSS and the cost of replaying dependency bytes at final selection still require measurement.

Prepared regressions compile genuine direct TSZ staged output and cover exact same-owner reuse, including an actual configured excluded source; mismatched input/binding and unregistered output; cold owner, cancellation and owner death; source content/removal/creation; a newly resolved negative candidate with an existing or absent intermediate parent; inherited config; dependency declaration/package exports changes; and same-byte dependency symlink retargeting. A typed outcome matrix rejects interrupted/refused semantic gaps and activated-runtime inference failure while accepting configured exclusions and the frozen embedding outcomes. Small transcript controls charge duplicate accesses to one resolver path, collection/object overhead, spare capacity and nested values; budget controls reject a charge above the remaining allowance and arithmetic overflow without allocating a giant invalid bridge fixture. The service regression checks cold/warm scanner tuple equivalence and changed-source invalidation. Existing unproven dynamic-read controls remain unchanged.
