## Contract

The normal CLI/MCP semantic-versions route now sends `SemanticVersionsPage`. Its page carries complete version metadata and an explicit `PublishedCatalog` header, followed by a contiguous segment of whole image proofs. The header commits to the complete original image set and final reference. It does not pretend a partial segment is the entire proof. `SemanticHistoryCatalog::assemble` admits the reconstructed original proof only after every exact ordinal, parent edge, image identity and aggregate commitment is present. A version appears as `first_segment` only once; subsequent segments retain the same version ordinal and source fields.

The page is built from one captured immutable owner snapshot: semantic/source roots, retained generations and selected source frontier all consume that same snapshot. The opaque bounded cursor retains the exact package, both relation roots, all version/source metadata and complete observed history identity, plus the next version/image position. It grants no mutation or publication authority. The owner checks those commitments against its own retained records; client admission checks the exact dispatched package, limit and continuation, without accepting the legacy reply family in place of the paged one or vice versa.

Default limit is eight whole image proofs (or versions without a published catalog); maximum is sixteen. The complete typed page is bounded to 12 KiB to reserve space for rows, readable text, continuation and the outer response envelope. The builder can return fewer whole items to fit that bound; it never clips a field or drops an undisclosed item. The outer CLI/MCP 49,152-byte budget and local four-MiB frame limit are unchanged. A single complete item that cannot fit is a distinct `WholeItemOversized` refusal, without misleading advice to lower its item count. Malformed cursors, stale bases, invalid catalogs and invalid limits remain separate producer error values.

CLI, human/Markdown output, MCP structured content and tools/list all expose the exact next read. `semantic_continue.shell` is an installed CLI command; `semantic_continue.call` is a literal MCP call containing package, limit, cursor and the caller's detail. Follow it unchanged until absent. This cursor remains an owner surface operand in the MCP router, rather than being interpreted as a query-page cursor. `semantic_data.value.entries[].version` is already the exact selected source operand for semantic-shapes; fetching all history proof images is not required for that read.

On a cold owner, the existing native history worker may need to reconstruct its derived proof sidecar. If semantic/source roots and every source/version field still match the saved cursor, an unfinished sidecar yields a bounded `Preparing` page with no images and the identical cursor. It advances only when the original complete history identity is restored. A changed source/version/root or a different terminal catalog refuses the saved continuation. This does not promote Pending/Deferred/Refused history to Published or reindex a project.

The original full `Session::semantic_versions`/`SurfaceCommand::SemanticVersions` API remains available for existing internal consumers, with its original full reply shape and exact package admission. Normal installed named reads use the new page. Live DTO becomes 29; persisted view rows, certificates and compact events remain unchanged, with historical journal envelopes 21 through 28 still admitted by the maintained checked grammar. The independent native-worker refusal cutover law remains explicitly DTO27 versus historical DTO28.

## Controls and remaining gates

All newly added controls are **UNRUN**. Source parsing by rustfmt and a clean diff check are not compilation or runtime proof.

- Library: a deterministic 133-image catalog based on the retained public 42-image schema must exceed the old reply allowance, then return complete bounded pages with every exact source, image and parent restored. Mixed retained versions must cross page boundaries without duplicated generations. Missing/reordered proofs, wrong package/limit, cursor jumps, cross-family replies and stale source/version roots are refused. Whole-item oversize is distinguished from a stale basis. The stateless serialized/reopened unit fixture checks an empty cold Preparing page and exact resumption; it does not simulate a daemon process restart.
- CLI: normal shared grammar/lowering, Session dispatch, actual versioned wire encode/strict decode/admission, full JSON and human/Markdown rendering follow literal returned continuations and reconstruct the original complete 42-image proof. Help and invalid limit controls match the maintained bounds.
- MCP: production JSON-RPC dispatch and complete stdio reply serialization follow copied calls at Summary, Standard and Full, admit each typed response against the dispatched command and reconstruct all 42 proofs. Tools/list describes the exact input and continuation shape. Existing source-to-shapes and Semver projection controls now use admitted page replies. The original oversized full-history display control remains at the production egress seam; it supplies no invalid page reply or fabricated compiler authority.
- Local service: an existing genuine native Python compiler fixture receives 133 distinct Python inputs and must reach Published under the existing 30-second operation bound. Production owner dispatch/strict wire admission checks the page against the actual semantic/source roots, verifies the old complete history exceeds 49,152 bytes, saves a real owner-issued cursor, reopens the fixture owner, and must restore the same source/catalog and exact image set without another indexing operation. Derived-history observation also retains a 30-second bound. It is a new genuine-producer gate, not an executed pass.
