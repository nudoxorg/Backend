## Implemented handoff

The adapter now admits one typed owned phase: Publication, Source, Cluster, Finalize, or Cleanup. The worker stores one private Preparation enum, including checked SourcePrepared and SourceCaptured continuations, rather than coordinated alternative payload Options. Existing head/writer custody states remain unchanged. A real scan-ready transition never calls synchronous finish_index_scan or publish_view. Completed profile frontier validation and configured-cluster compilation/local fallback use the same tracked writer handoff; there is no synchronous fallback on worker-start refusal.

Source preparation reads the captured immutable base, compares structural relations and compiler input witnesses, preserves admitted Python snapshot reuse, observes semantic candidates, materializes and hash-checks compiler sources, and prepares the source/Pending workspace candidate and coherent view. The worker checks the original revision fence again inside commit_product_selection_changes immediately before the normal selection/grant path. The actor receives only the checked fixed-size claim with the phase's exact cancellation token and uses the existing base/epoch and selected-source-closure grant fence. SourceCaptured installs the coherent candidate and exact source receipt while the operation remains Accepted. Compilation begins only after that installation and worker retirement. Final publication still independently claims Prepared and writes Published or PartiallyPublished.

Cleanup borrows its plan and frozen outcome in the enum across unwind. Every newly begun candidate attempt is also retained in the worker outside consumed payloads, so panic/error settlement can retire its exact identity before returning original writers. Failed cleanup stays Pending for explicit retry and cannot invent a different terminal outcome. The original semantic, operation-journal, projection and read-head writers are transferred, never duplicated. Large completed scans and displaced read owners are retired on a tracked, joinable worker. OS startup refusal restores capabilities first and uses tracked retirement; repeated retirement startup refusal retains the payload with a bounded retry interval. Shutdown joins the tracked worker before workspace teardown.
