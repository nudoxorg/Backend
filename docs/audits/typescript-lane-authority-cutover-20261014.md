# Native TypeScript lane authority cutover

Code parent: `bf40fcd895be01e87119afebb80724a6cda5d60a` on `codex/tsz-execution-cutover-20261014`, based on canonical `3aa8462a1a`. Root, Sol, and Luna cleared this code parent in source review. Native compilation, regression execution, and real project indexing are **UNRUN**. No ASP, GymBroApp, Guava, or zod recovery is claimed.

The current coordinator already checks each admitted forest program once, then lends its checked image to selected-file lowering. Canonical has the prepared/checked image states, sealed checker indexes, project views and shared pure query cache, exact module/file-format authority, admitted query-budget identity, and stop poisoning. PR 200 (`f008b015b2`, open and unmerged) contains older foundations; replacing current image code with that older branch would discard later lifetime and checked-image work. This cutover extends those current foundations.

The production coordinator previously constructed a new `TszProjectAuthority` for every forest node on every attempt. Its safe exact-repeat and source-edit reuse APIs therefore ended at a test/adapter boundary. The compiler now owns one authority lane in its existing worker scratch. The host still re-admits the complete compiler installation, configuration forest, membership, source bytes, resolver positive/negative reads, and fresh closure witnesses on every attempt. The lane retains only that package root's current real program keys; it prunes removed nodes, excludes solution nodes, rejects duplicate keys, and evicts the forest on a root change. Checking and lowering borrow those owners serially, without global locks or copying file checker environments. Ordinary exits restore lane ownership; unwinding discards its potentially incomplete state.

The full program environment includes dependency source bytes and resolver observations. It previously also invalidated every source bind, so a real edit defeated unchanged-source parse reuse. Bind identity now covers the actual parse/bind inputs: source path and bytes, parser target, module detection, and exact library content. A full environment, checker option, semantic option, exact module outcome, or file-format change still discards the checked image and all of its solver caches. Changed parser/binder options or library bytes also discard binds. Cached binders carry physical declaration-arena provenance, so equal re-admitted library bytes retain the original library objects while source binds survive; a content change replaces both.

The existing work allowance, deadline, cancellation semantics, source coverage, and publication checks remain authoritative. A stopped image cannot lend another query session; the next update rebuilds it. No failed source is dropped to produce a complete result. Mutable file-local memo entries and evaluator/flow environments remain local to their actual checker. They are not promoted to another source, environment, or program.

At WARN level, the first observed stopped checkpoint now captures the active native phase, exact admitted file when available, program index, worker, admitted source/library/module-request counts, started checks, completed postprocessed checks, reused checks, and the existing allowance/charge snapshot. Thread-local boundary stacks contain observation data only. A source check's return alone does not count as completion because it may have converted a stop into a sentinel. Count sampling observes published completions before starts. `FileQuery` boundaries also expose lazy lowering work. The fields describe the first observed failed checkpoint; another worker may have latched the original stop, so this is not a claim that the observed file originated every unit of prior work. The public terminal still carries the existing typed stop/site, and an unavailable file context does not invent a hot file. Detailed boundary logs remain DEBUG-only. Observation has allocation, atomic, and elapsed-time overhead and must be measured.

Prepared native controls cover dependency-type edits versus a cold program; semantic options versus parser/binder options; library object provenance; root/config node pruning; duplicate program authority rejection; actual checked-image query boundaries; poisoning and later budget scopes; WARN-only phase/file/count capture; and genuine pinned Compiler API production repeats followed by selected-source, external declaration, and configuration edits. These are source-present controls, not passing receipts. Local `rustfmt --emit stdout` parsing and `git diff --check` pass; no local Cargo build was started.

The residency change is material: one complete admitted forest can remain in each existing compiler lane while idle. There is no cross-package cache or new worker actor, but the retained program/interner/solver memory requires peak and idle RSS measurement under the fleet's actual admission and CI reservation before rollout. A root change evicts rather than accumulating programs. This cutover avoids repeat work; first-import generic checker exhaustion remains an empirical question.
