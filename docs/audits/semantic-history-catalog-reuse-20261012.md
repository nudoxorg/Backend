# Reuse an immutable semantic-history catalog

This successor builds on the source-only lossless history-page atom `a467f893eb1cb10fd26a3cc6cf46d8abb8e7f886`. The actual cb57 HTTPie 97,758-byte refusal remains historical evidence. Neither the page atom nor this successor has compiled or run on a current installed binary.

The first page implementation materialized, admitted and hashed the full retained history on each request. For P pages containing N images, this repeated O(P × N) catalog work; the synthetic 16,384-image structural case requires at least 2,048 default pages. A response-size bound alone did not repair that read cost.

## Immutable derived observation

`SemanticVersionsCatalog` consumes the complete owned observation once. Its public constructor admits every full record, requires the exact selected source relation root, and hashes the same complete records and history-independent metadata with the original domains. It retains those immutable full records and precomputes only small paged version/catalog headers. Each page indexes its exact version/image offset, copies requested whole images and the preceding edge, and mints the same cursor schema and exact basis. It never re-admits or rehashes the complete catalog. The compatibility `SemanticVersionsPage::from_versions` still constructs an observation per call; the normal owner route uses the retained catalog.

The owner stores one immutable `Arc` catalog slot. Its key is the exact package, full admitted workspace root, explicit semantic/source relation roots, and the exact allocation identities of the serving selected-product/closure-binding, status/in-flight, freshness-history, retained-generation and committed-observation inventories. The full workspace root covers all captured relations, including changes affecting source/freshness even when one queried relation root is unchanged. Inventory pointer identity is an internal invalidation key only; it is never a wire authority or cursor commitment. Updating an inventory while its strong captured reader or weak cache guard exists dissociates its old allocation identity; neither reader nor cache can be mistaken for the changed view. Cache checks require every key component and the exact package. Alternating packages replace this one count-limited slot rather than accumulating catalogs. The frozen 9527 implementation limited slot count only: it retained complete catalog proofs and strong inventory guards that could pin unrelated owner-map backing. The separate successor described below removes those strong cache guards and admits a scoped allocation charge.

The derived catalog is built lazily when a new committed observation first enters the read projection. Native history completion drains once before projection. Every selected key is first scheduled without cloning complete proof payloads. Only after those requests have finished does the builder capture one immutable bounded inventory, including its in-flight identities, and project every record from it without draining or scheduling. This also handles FIFO eviction during request scheduling: an earlier selected key aged out by later requests is projected from the final inventory as NotRequested/Pending, never cached as a terminal row absent from its key. The complete resulting inventory is strongly captured while records are projected; its exact weak allocation identities are retained when the catalog is installed. The next read sees a completed or changed inventory and rebuilds. Index-writer detachment shares the same immutable catalog and actual captured status roots with reads; a changed writer inventory cannot overwrite an admitted reader. Returning that writer requires fresh-key validation before reuse.

The bounded native status inventory is copy-on-write `Arc<VecDeque<...>>`; each status payload is itself an immutable `Arc`. Selector/retry checks borrow the status, so a routine owner poll does not clone a complete Published payload. The existing serving-selector read lock is held only to clone/check its immutable map guards, never around paging, hashing or cache preparation. A captured index reader takes no mutable selector lock. Catalog installation checks that the serving guards stayed identical through preparation; a changed selector refuses installation rather than retaining a mixed observation. Construction still makes one full legacy-record projection copy on a cache miss and admits/hashes its complete catalog. No global cache, mutex, new queue, persistent cursor state, mutation replay or publication authority is added.

## Work controls and limits

`SemanticHistoryReadWork` records logical full-record/image admission and full JSON commitment bytes during construction, and copied images/measured bounded candidates during page generation. It is structural accounting, not elapsed-time or inference proof. Page framing admission and normal outer presentation/wire accounting still execute; only the complete retained catalog work is eliminated from repeated pages. At most sixteen requested whole items and a fixed 12-KiB typed response remain unchanged. Candidate retries may copy/measure fewer complete items several times, but their work is bounded by the page limit and public field bounds, rather than total catalog length.

The new 16,384-image unit law scales the retained public schema, consumes it into one admitted catalog, walks every image and parent without gaps/duplicates, and requires zero full-catalog admissions/hash bytes on every page. It records linear bounded candidate work, exact proof reassembly, zero work on invalid limits, and a stateless cold reconstruction producing the same saved-cursor page and one complete rebuild. It is explicitly synthetic catalog authority, not native compiler output or a maximum-size project/history gate. The 16,384 value comes from the package-membership fixture constant, not a global semantic-image limit. The selected Project frontier separately permits 100,000 files, and the persisted history locator separately permits 200,000 objects. These distinct limits do not establish a cache-residency bound; their maximum-size runtime behavior remains unrun.

A separate bounded-inventory control fills/evicts the original status FIFO while retaining an older guard, distinguishes final Pending from the earlier Deferred row, then retires the live in-flight identity and requires the old guard to remain Pending while the fresh guard reports NotRequested. It supplies checked stamp shape and derived status values only, with no Published authority.

An authority control uses an actual private Turso owner with an empty admitted catalog. It proves same-owner/package reuse, foreign package isolation, immutable read sharing across unique writer transfer, copy-on-write status invalidation before/after writer return, and count-limited slot replacement. It additionally forces same-root selector reconciliation under an owned guard, requires copy-on-write invalidation, and refuses catalog installation across that captured selector change. Its checked synthetic stamp tests shape/ownership only; it never creates Published compiler evidence.

The existing genuine 133-input NativePython gate retains every publication, exact source/root, full old-size, complete image/parent reassembly, no-reindex and 30-second assertion. New counters require a real hot owner continuation to reuse the same prepared catalog without full admission/hashing, then require exactly 133 image admissions on cold completion and no recurring complete work through the remaining page walk. Pending cache construction may occur before the original history becomes Ready; it never advances the saved cursor.

All controls, type checking, compilation, full suites and same-source installed CLI/MCP runtime reads are **UNRUN**. Source parsing and diff review are separate from those gates. No response/frame cap, timeout, original assertion, coverage or failure receipt is changed.

## Separate requested-allocation retention successor

The source-only baseline `9527e9735b0ea17469c2b9d8dc7f320be4636866` remains frozen. This separate successor applies a 32-MiB per-slot charge for retained requested allocation storage. It is a derived-cache policy, not a history capability limit or a process RSS/allocator-fragmentation guarantee. Catalog preparation, page candidates and legitimately retained reader snapshots remain separate transient/reader costs. Detachment may create two roles sharing one catalog allocation; each slot conservatively charges the whole shared catalog rather than discounting it. The counters describe this scoped charge, not unique process memory.

The key owns seven `Weak` identities: the two selected inventories plus status, in-flight, freshness history, retained generations and committed observations. Strong admitted snapshots remain alive during catalog construction and its before/after selector checks. With an outstanding `Weak`, `Arc::get_mut` refuses; `Arc::make_mut` creates a distinct allocation and either clones or moves the value, dissociating the old weak identity. The weak allocation remains owned against pointer reuse until its last weak guard drops. Its control block and inline collection header remain allocated, while the collection and transitive proof backing are released when no strong owner remains. Cache comparison never upgrades a weak guard. This uses the actual allocation identity; no pointer is serialized as cursor authority.

`SemanticVersionsCatalog::retained_allocation_bytes` makes a checked census of its inline value, both owned record/header buffers, every nested owned string capacity or boxed text extent, all complete image/parent slices, and selected-source package text. Record/status/proof/header fields are exhaustively destructured so adding fields requires a source accounting decision. The owner additionally charges inline slot fields, the catalog control allowance, and all seven weak control/header allocations. Each control allowance is two pointer-width counters plus one alignment unit; it conservatively includes supported `Arc` header padding, without claiming allocator metadata or size-class accounting. Entire shared allocations are charged per slot, even while another legitimate owner also holds them. Encoded JSON size is never used as a resident-size proxy.

Checked overflow or a charge above the allowance clears the retained slot only and returns the same complete request-local admitted catalog/page. Full proof content, exact source/basis commitments, saved cursors, response limits and capability admission are unchanged. Such uncached pagination may repeat O(P × N) preparation work; there is no claim that the largest supported history fits the cache. A proven cache miss drops its stale slot before replacement construction; a real reader retaining its own catalog `Arc` remains valid. The implementation does not prevent transient replacement/catalog construction from exceeding the cache allowance.

Three additional controls cover full proof/header/parent and string-capacity accounting; exact byte-boundary retention, one-byte-over fallback, checked overflow, and a production-policy oversized spare capacity with complete proof and unchanged saved cursor; and weak-only mutation invalidation plus nested payload release after the last strong inventory owner drops. The public DTO is captured fixture shape, not compiler authority for the test owner. The existing package-replacement control checks the matching slot before its intentional foreign-key miss, then additionally requires early retirement; all prior package-isolation assertions remain. The synthetic 16,384-image law's source comment now explicitly rejects a global-bound interpretation.

The twenty-two source selectors, compilation, full suites, genuine 133-input gate and same-source current CLI/MCP/cold-runtime obligations are **UNRUN**. No native workload or benchmark has run for this resident successor. The original oversized-response refusal and unchanged frame/response/time limits remain preserved.
