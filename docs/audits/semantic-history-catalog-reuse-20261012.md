# Reuse an immutable semantic-history catalog

This successor builds on the source-only lossless history-page atom `a467f893eb1cb10fd26a3cc6cf46d8abb8e7f886`. The actual cb57 HTTPie 97,758-byte refusal remains historical evidence. Neither the page atom nor this successor has compiled or run on a current installed binary.

The first page implementation materialized, admitted and hashed the full retained history on each request. For P pages containing N images, this repeated O(P × N) catalog work; the maintained 16,384-image bound could require at least 2,048 default pages. A response-size bound alone did not repair that read cost.

## Immutable derived observation

`SemanticVersionsCatalog` consumes the complete owned observation once. Its private constructor admits every full record, requires the exact selected source relation root, and hashes the same complete records and history-independent metadata with the original domains. It retains those immutable full records and precomputes only small paged version/catalog headers. Each page indexes its exact version/image offset, copies requested whole images and the preceding edge, and mints the same cursor schema and exact basis. It never re-admits or rehashes the complete catalog. The compatibility `SemanticVersionsPage::from_versions` still constructs an observation per call; the normal owner route uses the retained catalog.

The owner stores one immutable `Arc` catalog slot. Its key is the exact package, full admitted workspace root, explicit semantic/source relation roots, and the exact copy-on-write serving selected-product/closure-binding, status, freshness-history, retained-generation and committed-observation inventories. The full workspace root covers all captured relations, including changes affecting source/freshness even when one queried relation root is unchanged. Inventory pointer identity is an internal invalidation key only; it is never a wire authority or cursor commitment. Updating any inventory while a slot retains it makes a new immutable snapshot. Cache checks require every key component and the exact package. Alternating packages replace this one bounded slot rather than accumulating catalogs.

The derived catalog is built lazily when a new committed observation first enters the read projection. Native history completion drains once before projection. Projecting each selected record uses that already-drained inventory without taking another completion between records. Scheduling an absent selected history may add its own Pending/Deferred record; the complete resulting inventory is retained when the catalog is installed. The next read sees a completed or changed inventory and rebuilds. Index-writer detachment shares the same immutable catalog and status roots with captured reads; a changed writer inventory cannot overwrite an admitted reader. Returning that writer requires fresh-key validation before reuse.

The bounded native status inventory is copy-on-write `Arc<VecDeque<...>>`; each status payload is itself an immutable `Arc`. Selector/retry checks borrow the status, so a routine owner poll does not clone a 16,384-image Published payload. The existing serving-selector read lock is held only to clone/check its immutable map guards, never around paging, hashing or cache preparation. A captured index reader takes no mutable selector lock. Catalog installation checks that the serving guards stayed identical through preparation; a changed selector refuses installation rather than retaining a mixed observation. Construction still makes one full legacy-record projection copy on a cache miss and admits/hashes its complete catalog. No global cache, mutex, new queue, persistent cursor state, mutation replay or publication authority is added.

## Work controls and limits

`SemanticHistoryReadWork` records logical full-record/image admission and full JSON commitment bytes during construction, and copied images/measured bounded candidates during page generation. It is structural accounting, not elapsed-time or inference proof. Page framing admission and normal outer presentation/wire accounting still execute; only the complete retained catalog work is eliminated from repeated pages. At most sixteen requested whole items and a fixed 12-KiB typed response remain unchanged. Candidate retries may copy/measure fewer complete items several times, but their work is bounded by the page limit and public field bounds, rather than total catalog length.

The new 16,384-image unit law scales the retained public schema, consumes it into one admitted catalog, walks every image and parent without gaps/duplicates, and requires zero full-catalog admissions/hash bytes on every page. It records linear bounded candidate work, exact proof reassembly, zero work on invalid limits, and a stateless cold reconstruction producing the same saved-cursor page and one complete rebuild. It is explicitly synthetic catalog authority, not native compiler output.

An authority control uses an actual private Turso owner with an empty admitted catalog. It proves same-owner/package reuse, foreign package isolation, immutable read sharing across unique writer transfer, copy-on-write status invalidation before/after writer return, and bounded slot replacement. It additionally forces same-root selector reconciliation under an owned guard, requires copy-on-write invalidation, and refuses catalog installation across that captured selector change. Its checked synthetic stamp tests shape/ownership only; it never creates Published compiler evidence.

The existing genuine 133-input NativePython gate retains every publication, exact source/root, full old-size, complete image/parent reassembly, no-reindex and 30-second assertion. New counters require a real hot owner continuation to reuse the same prepared catalog without full admission/hashing, then require exactly 133 image admissions on cold completion and no recurring complete work through the remaining page walk. Pending cache construction may occur before the original history becomes Ready; it never advances the saved cursor.

All controls, type checking, compilation, full suites and same-source installed CLI/MCP runtime reads are **UNRUN**. Source parsing and diff review are separate from those gates. No response/frame cap, timeout, original assertion, coverage or failure receipt is changed.
