--- 1.0 The route model (what exists as a type) ---

ROUTE-TYPE. desktop/navigation/route.rs:204-213 defines Route as four variants: Orbit(OrbitRoute), Package(PackageRoute), Symbol(SymbolRoute), World. OrbitRoute (route.rs:71-79) has Home, Project(ProjectId), Browse(BrowseRoute). BrowseRoute (navigation/browse.rs:52-61) has Tree(LocalProjectId), FindHome, Find(SearchQuery), Compare(CompareSet). View (route.rs:138-146) has Page, Code, Graph. PackageLane (route.rs:122-133) has Overview, Dependencies, Dependents, Releases, Security. Overlay (route.rs:217-226) has AddProject, Settings(SettingsPage), CommandPalette, Inbox. SettingsPage (route.rs:230-252) has ten pages: Appearance, Editor, Agents, Connections, Privacy, Diagnostics, Index, Registry, Legend, Help.

ROUTE-DEAD-1 PackageLane. Only Overview is ever constructed by product code (grep "PackageLane::" finds Overview at shell/kit.rs:310, shell/side/hold.rs:97, shell/side/scope.rs:184, shell/symbol_links.rs:210, shell/root.rs:1590, runtime/ui_graph.rs:469, route.rs:366). Dependencies/Dependents/Releases/Security appear only in the persistence round-trip (model/persistence.rs:405-421). The package body ignores the lane entirely: shell/bodies/package.rs:34-143 never reads route.lane. So a saved session file with lane=security would render the Overview page. No UI sets a lane.

ROUTE-DEAD-2 OrbitRoute::Project. Constructed only by (a) Route::zoom_out from a Package/Symbol route whose `project` is Some (route.rs:370-374), (b) persistence restore (model/persistence.rs:851). Every product constructor of PackageRoute/SymbolRoute passes `project: None` (grep "project: Some" finds only a route.rs unit test at :474 and source_facts). So the "project orbit" is never reached by a person. It also has no body of its own: shell/bodies/mod.rs:332 sends every Route::Orbit(_) that is not Browse to orbit::body, the same page as Home. jump.rs:244-248 gives it the capsule name "Project / orbit" that nothing shows.

ROUTE-DEAD-3 BrowseRoute::Tree. Constructed only by the harness (harness.rs:903 route::to_route Target::Tree, harness.rs:1193) and unit tests. No click, key, menu, Ask row or sidebar row navigates to it (grep "BrowseRoute::Tree" across desktop/src finds no shell constructor). The Tree body (the "Library" page with alerts / roles / duplicates, shell/bodies/browse.rs:38-41, library_model :122-198) is therefore unreachable by a person; it exists only as `--start tree` in the harness.

ROUTE-DEAD-4 BrowseRoute::FindHome. Constructed by the harness (harness.rs:906) and by the reducer when a Find query is cleared (navigation/reducer.rs:54). There is no control that opens Find with an empty query: Find is entered only with a non-empty query from Ask "all results" (shell/ask.rs:207), the sidebar "Widen" row (shell/side/mod.rs:319), and a symbol-page lookup fallback (shell/bodies/symbol/host.rs:136).

ROUTE-DEAD-5 BrowseRoute::Compare. Reachable only from inside a Find page: the compare action (shell/bodies/browse.rs:87-92) with 2..4 held packages. There is no other entry.

ROUTE-PERSIST. Persisted session never stores a browsing page: model/persistence.rs:787-792 writes Orbit::Browse(_) as PersistedRoute::Home ("its route is not a persisted shape yet"). Find, Compare and Tree do not survive relaunch.

--- 2.1 The typed action layer in navigation/action.rs is dead ---

ACTION-LAYER. SECTION 6. PLATFORM
======================================================================

Summary: the shell is built and exercised on macOS only. Windows and Linux compile paths exist (target-specific gpui_platform features, apps/desktop/Cargo.toml:65-72; the repo's `.#cross` shell compile-checks them) but nothing runs there, and several product behaviours are macOS-shaped or plain wrong off macOS.

--- 6.1 macOS-specific things that exist ---
MAC-TITLEBAR-INSET. shell/titlebar.rs:129: `let inset = if cfg!(target_os = "macos") { px(78.0) } else { measure.space(Space::Roomy) };` - the jump bar is padded 78 px left to clear the traffic lights. Window options set `TitlebarOptions { appears_transparent: !cfg!(any(linux, freebsd)), traffic_light_position: Some(point(px(14.0), px(14.0))) }` (host/launch.rs:409-415). A hard-coded 78 px does not follow the traffic-light position/size and does not scale with text zoom.
MAC-TITLEBAR-DRAG. The bar is a drag region via `.window_control_area(WindowControlArea::Drag)` (titlebar.rs:187). No Min/Max/Close control areas or buttons exist anywhere in desktop/src, and facet's chrome::titlebar (which has painted stand-in lights, chrome/titlebar.rs:47,385) is unused by the desktop (section 2.7).
MAC-BUNDLE. apps/desktop/package-macos.sh builds `target/Nudox.app`: copies the binary to Contents/MacOS/Nudox and macos/Info.plist to Contents/Info.plist, prints the path. Info.plist (macos/Info.plist): CFBundleIdentifier dev.nudox.desktop, version 0.1.0, LSMinimumSystemVersion 12.0, NSHighResolutionCapable. Missing: an icon (no CFBundleIconFile; Contents/Resources is created empty), a URL scheme for `nudox://` (the address bar shows and copies nudox:// addresses, root.rs:1126-1128, jump.rs:335-345, but nothing registers or handles the scheme: no open-url handler in desktop/src), document types, code signing, notarisation, entitlements, a dmg/zip, an updater.
MAC-FONTS. Fonts are embedded in the binary with include_bytes! (facet/src/fonts.rs:71-78, 18 cuts, sha256-verified at install, facet/src/fonts.rs:274-283) and installed at start (host/launch.rs:402-405 `install`, calling `facet::fonts::install(cx)`), so text does not depend on system fonts on any OS. apps/desktop/resources/fonts (Archivo, GeistMono, Instrument Sans, Newsreader; README.md) is referenced by no code in desktop/src or Cargo.toml: leftover.
MAC-DATA-DIR. host/paths.rs:97-125: ~/Library/Application Support/Nudox on macOS; %APPDATA%\Nudox on Windows; $XDG_DATA_HOME/nudox else ~/.local/share/nudox elsewhere. These branches exist for all three; only the macOS one is exercised.
MAC-QUIT-SAVES. cx.on_app_quit handlers save the launch snapshot and close the owner gate (host/launch.rs:356-375). No app menu: grep for set_menus/Menu/dock/on_reopen/open_urls in desktop/src finds nothing. Consequences (from code; not run): no macOS menu bar items at all (no Quit ⌘Q, Hide ⌘H, Minimise ⌘M, Close window ⌘W, About, Services, Window menu); no Dock menu; no reopen-on-Dock-click handler; no quit-when-last-window-closes handler (grep `quit()` finds none). Whether GPUI supplies default Quit/Hide bindings is outside this crate; nothing here binds them.
MAC-FILE-PICKER. The native folder panel is gpui's prompt_for_paths via runtime/ui_graph.rs start_folder_picker (Intent::OpenFolderPicker at ui_graph.rs:236); outcomes Selected/Cancelled/Unavailable/Failed (navigation/intent.rs:58-69) are typed, so the Linux "no portal" case (Unavailable) has a message path (workspace_reducer.rs:136-141). Exercised only in reducer tests; no journey drives the panel (install-by-picker part unused).
MAC-REVEAL-IN-FINDER. Intent::RevealProject -> cx.reveal_path(&project.path()) (ui_graph.rs:238): gpui's cross-platform reveal (Finder on macOS, file manager elsewhere). The row/card label says "Reveal", not "Reveal in Finder".
MAC-OPEN-IN-EDITOR. host/editor.rs:60-78: configured command (unset: SETTINGS-EDITOR in section 2.3), then `code -g path:line`, then `zed path:line`, then `open path` on macOS or `xdg-open path` on everything else. On Windows the fallback is `xdg-open` (does not exist) and `code` resolves to code.cmd, which a bare Command::new("code") may not find; both are unverified. The opener is passed the file only, never the line (editor.rs:76, `args: vec![path]`).
MAC-CLIPBOARD. ⌘⇧C copies the nudox:// address with cx.write_to_clipboard (root.rs:1126-1128).
MAC-TEXT-SIZE. shell/system.rs:31-69: macOS exposes no system text size to the app, so the baseline is 1.0 and only ⌘+/⌘-/⌘0 (per display, keyed by display UUID) move it; Linux reads gsettings text-scaling-factor (GNOME only; KDE/others fall back to 1.0); Windows reads HKCU\Software\Microsoft\Accessibility TextScaleFactor by spawning `reg`. All three spawn a process on the background executor.
MAC-WINDOW-RESTORE. Only the window SIZE is remembered (host/window_size.rs; WindowResized intent after a 400 ms rest; clamped 320x480 .. 8192; opening default 1380x880, host/launch.rs:38-39). Position is not remembered (always Bounds::centered, launch.rs:408); maximised/full-screen is deliberately not restored (window_size.rs:56); the display a window was on is not restored; one window only (a single global Kept memory, window_size.rs:37-41; no ⌘N new window: ⌘N is not in the key table, and "New window" has no menu).
MAC-KEYS. The key table uses gpui's `secondary` (⌘ on macOS, Ctrl elsewhere) for shell chords (keys.rs:8-9, 178) and literal `ctrl-` for depth (keys.rs:227-230). Caps are hard-coded macOS glyph strings ("⌘K", "⌘⇧C", "⌃1", "⌥" x-ray) used by Settings › Keys, the ⌘-hold key-cap reveal and the titlebar's "⌘K" cap (titlebar.rs:484).

--- 6.2 Things that are wrong or missing off macOS (from code) ---
PLAT-KEY-COLLISION. Off macOS `secondary` is Ctrl, so the hand cards ⌘1-⌘5 (`secondary-1`..`secondary-5`, keys.rs:234-238) bind the same chord as the depth keys `ctrl-1`..`ctrl-4` (keys.rs:227-230): Ctrl-1 is both "Orbit" and "the hand's first card", Ctrl-2..4 likewise. The uniqueness test compares the spelled strings only (keys.rs:332-337: "secondary-1" != "ctrl-1"), so it cannot see this.
PLAT-REVEAL. The hold-to-reveal key caps arm on `modifiers.platform` alone and are disarmed by `modifiers.control` (shell/reveal.rs:58-60). On Windows/Linux `platform` is the Super/Windows key while the shortcuts use Ctrl, so holding the shortcut modifier (Ctrl) never shows the caps and holding the Super key shows caps for keys that are Ctrl chords.
PLAT-CAPS-LIE. Every cap string and copy line says ⌘/⌥/⌃ regardless of platform (keys.rs:199-241; onboard/library.rs "or press ⌘O"; Settings › Keys).
PLAT-WINDOW-CONTROLS. Windows: `appears_transparent: true` (launch.rs:413) hides the system caption while the shell draws no minimise/maximise/close controls (section 6.1 MAC-TITLEBAR-DRAG) and pads only Roomy left; whether gpui's Windows backend still draws caption buttons over a transparent title bar is not established by this crate. Linux: appears_transparent is false (a native title bar where the compositor draws one), while the shell still lays out its own titlebar region inside the client area (shell/frame.rs titlebar), so there can be two bars (from code; not run).
PLAT-ENDPOINT. The owner endpoint is a Unix-domain socket path ("the endpoint is a separate socket", host/lease.rs:2; host/paths.rs:2 hash of the data dir; harness endpoints under /tmp/nx-harness-*.sock, harness.rs:228-236). No named-pipe or Windows-specific endpoint code exists in apps/desktop. Whether crates/local-service supports Windows is outside this inventory (not checked).
PLAT-TOOLCHAIN. host/toolchain.rs find_rust searches Homebrew (/opt/homebrew/bin, /usr/local/bin), rustup, Nix, PATH; no Windows locations (%USERPROFILE%\.cargo\bin, Chocolatey/Scoop) and no distro package paths. Go module cache only via NUDOX_GO. The Rust-missing copy says "Install Rust with rustup (rustup.rs) or Homebrew (brew install rust)" (onboard/failure.rs).
PLAT-HARNESS. The whole harness is Unix/macOS: `cp -Rc` APFS clone (harness/journey/state.rs:334), rustix (cfg(unix) dep), UDS sockets under /tmp, a 0700 umask requirement (harness.rs:628-650). Journeys, scenes and screenshots cannot run on Windows.
PLAT-TESTS. Unit tests with `#[cfg(unix)]` (harness.rs:629,639,1957,1984; host/mod.rs:29; registry/archive.rs:206; core/ids.rs:637) and a `cfg(not(unix))` branch in only one helper (host/mod.rs:39). Text-size code has Windows and Linux branches with no test (shell/system.rs).
PLAT-LINUX-WAYLAND. Cargo enables x11 and wayland for linux/freebsd (Cargo.toml:68-70); the shell has no Linux-specific behaviour beyond gsettings, appears_transparent=false, XDG data dir and xdg-open; under apps/desktop there is no .desktop file, icon, AppImage/deb/flatpak packaging (only macos/Info.plist and package-macos.sh). Windows: no installer, no resource file/icon, no manifest.
PLAT-ACCESSIBILITY. No accessibility tree is published by the shell: navigation/action.rs defines AccessibilityRole/ActionNode but nothing uses them (section 2.1); a grep for accessib/a11y/aria/accesskit in desktop/src and facet/src finds only doc comments (core/ports.rs:29, core/state.rs:20). So VoiceOver/Narrator/Orca see whatever GPUI exposes by default; no code here labels anything for them.
