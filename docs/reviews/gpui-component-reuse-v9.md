# GPUI component reuse audit v9

This is an adversarial, read-mostly audit of the Nudox desktop component seam. It compares the vendored `gpui_ce_components` façade (`gpui_component` in application imports) with the published `gpui-ce 0.2.2` and `gpui_ce_components_base 0.2.0` sources, then checks the active component worktrees for behavior that is already owned by CE.

The repository pins `gpui-ce = 0.2.2` and `gpui_ce_components = 0.2.0`; Cargo patches the latter to `vendor/gpui_ce_components`. The published source snapshots used for the audit are:

- `vendor/gpui_ce_components/`
- `/Users/mileswirht/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-ce-0.2.2/`
- `/Users/mileswirht/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui_ce_components_base-0.2.0/`

The local façade contains the existing A11y additions to `Button` and `Input` (`accessibility_description`, focus/hover/press observation, and `tab_stop`). Those are part of the current vendor baseline and are a collision boundary for any proposed vendor change. This audit also adds a small, separate façade re-export of the published `gpui_base` text-selection protocol under `gpui_component::text`; it does not change Button/Input behavior.

## Decision rules

CE should own focus traversal, keyboard activation, IME and text editing, selection, popup placement and dismissal, menu/list navigation, and virtualized rendering. Nudox should own producer truth, stable identities, routes, query admission, domain selection, responsive tokens, and deterministic app timelines. A raw `div().on_click`, a second popup state machine, or a second culling loop is a reuse defect unless the code is only an app adapter around a real CE element.

The feedback lane's `Notification::with_id` patch is a convenience duplicate of the existing `Notification::new().id1::<T>(key)` API. The docs chrome lane's `BreadcrumbItem::focusable` patch is a valid accessibility seam, but it should be reviewed with the existing Button/Input A11y work rather than copied into a second vendor commit. The only vendor addition here is commit `80d4c6221`, which exposes the already-published `gpui_base` text-selection types from `gpui_component::text` for virtualized text adapters.
