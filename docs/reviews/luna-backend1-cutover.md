# Backend v2 versus backend_1: cutover review

Date: 2026-09-09

This is an executable-code review. I read each repository's root manifests, README and review/operations material, then followed the binaries, dependency edges, and tests. The old checkout is a useful capability oracle but is currently a dirty migration checkout; its root metadata does not resolve. The new checkout's workspace tests pass after a rerun, but the passing graph is the bounded engine/app contract graph, not the old product's catalog/index/compile graph.

## Decision

The cutover is **not releaseable**. Backend v2 currently supplies a coherent versioned object/relation engine, durable local store, protocol adapters, and deterministic extension contracts. It does not supply a runnable replacement for backend_1's live catalog, compiler-to-index ingestion, DoltLite/Turso catalog, async Trustfall query plane, GPUI desktop, or real Tantivy/Qdrant projections. The old product paths are explicitly excluded from the new workspace while still being the only source of several production capabilities.

The highest-risk false positive is the repository shape: the new README calls the excluded trees “compatibility oracles,” while their manifests and source are not merely test fixtures. For example, backend_1's `workspace/index` has an `ingest` binary, `nudox-serve` binary, real DoltLite engine, migrations, pollers, HTTP routes, and live backend tests. None is reachable from the new root workspace.

## Evidence and reproducibility

The new root `Cargo.toml:1-23` says legacy source is deliberately absent and excludes `compiler/*`, `heart/*`, `interface/*`, `server/*`, `server/index/*`, and `server/index/turso`. Its workspace members are only `crates/*`, `frontends/*`, `extensions/*`, `apps/*`, `tests/*`, and `tools/*` (`Cargo.toml:6-12`). `cargo metadata --no-deps --offline` therefore reports the 24 bounded packages; it reports no `server-index-*`, compiler driver, or GUI package.

The requested path is not a product crate: `cargo check --manifest-path server/index/Cargo.toml --offline` fails with `manifest path ... does not exist`. There are manifests below it, but no parent composition manifest. Those leaves are not independently buildable against the new root either: `server/index/catalog/Cargo.toml:15` inherits `turso.workspace = true`, although the new root has no `turso` workspace dependency; `server/index/trustfall/Cargo.toml:17-18` inherits `trustfall.workspace` and `trustfall_core.workspace`, although the new root defines neither.

The documented new checks in `README.md:17-24` are useful closure checks: metadata, the cutover journey script, offline workspace tests, clippy, and Python prototypes. `cargo test --workspace --all-targets --offline -q` passed on the rerun, with warning/`kill: ... No such process` noise from the process-oriented tests. The first run had a `backend_compile` supervisor test failure (`kill: <pid>: No such process`); this should be made deterministic before using it as a release gate. The passing tests exercise local contracts, synthetic fixtures, and protocol state machines; they do not prove a live package can be acquired, compiled, published, indexed, and queried.

The old root `Cargo.toml:11-76` names the historical product workspace, including `workspace/index`, compiler/languages, heart, registry, transport, IR, and engine components. The current old root cannot be used as a clean baseline: `cargo metadata --format-version 1 --no-deps --offline` fails because the manifest references `/Users/mileswirht/Downloads/backend_1/workspace/ir/model/Cargo.toml`, while the checkout has that source under a different migration path. The `workspace2` transition metadata also fails because it expects `workspace2/crates/compiler/Cargo.toml`, which is absent. Treat backend_1's source as capability evidence until a pinned, clean historical tag/branch is restored; do not delete it based on an unbuildable migration checkout.

The new repository's all-branch history contains Trustfall/index work (including async semantic-image, borrowed graph projection, S3 projection, and `codex/typed-trustfall-product-query-20260906`/`codex/trustfall-adapter` branches), but the current HEAD has neither the fork dependency nor a merge/build path for that work. No remote PR identifier or lockfile provenance is present in the current product manifest. This is an integration gap, not evidence that the branches are production-ready.

## Release blockers

### P0 — do not cut over

1. **No runnable product index path.** Add one product composition target to the new workspace and prove source acquire → compile → IR/publication → catalog/snapshot → exact/lexical/semantic/graph query through a process boundary. The current `apps/locald`, CLI, and MCP can pass a generic protocol while there is no index service to call.
2. **No catalog backend.** Decide and implement the Turso contract requested under `server/index/turso` (or an explicitly approved replacement), restore its workspace dependency/pinning, add schema/migrations/checkpoint reopen tests, and make the catalog part of the product binary. The old `DoltEngine` behavior and default real-engine mode are the minimum parity reference.
3. **No async Trustfall integration.** Pin the user's fork/recent PR in a buildable workspace dependency, port the adapter/query/runtime boundary, and run an actual graph query over a published snapshot. The current synchronous `MemorySource` extension is not a query engine or a fork integration.
4. **No live ingestion or multi-language terminal.** Wire the seven language frontends to real package producers and publication, then run a bounded corpus E2E with negative/parse-failure cases and fan-out checks. A fixture that emits an identity envelope cannot close this blocker.
5. **No launchable desktop parity.** Either ship a real GUI binary that composes the new engine/index/MCP, or explicitly remove desktop from the claimed replacement scope. A reducer library cannot be the backend_1 GPUI product.

### P1 — required before production replacement

1. **Bind CLI/MCP to real query services.** Add golden tests for `search`, `outline`, `document`, `graph`, and error/certificate behavior against the same durable corpus, over both local and remote transports.
2. **Close restart/recovery.** Recover catalog, index projections, feed watermarks, worker leases, and pending outbox work after process kill. Fix the documented locald pending-envelope loss and reconnect circuit; add a TCP locald-to-worker process journey (the current review identifies Unix coverage but no composed TCP Product journey at `docs/reviews/sol-final.md:142-145`).
3. **Publish setup and configuration.** Define one supported command/configuration path for catalog location, feed credentials/URLs, object/index/semantic endpoints, migrations, health/readiness, and shutdown. Exercise it on a clean machine/container.
4. **Repair the old baseline before deletion.** Restore a pinned old tag/branch whose root and transition manifests resolve, or archive a complete source+lockfile artifact. Current path drift makes a parity comparison and deletion decision non-reproducible.
5. **Record Trustfall provenance.** A local branch name is not integration. Record the exact fork/PR commit, lockfile source, license/security review, and a build/test command in the new repository.
6. **Preserve ingestion watermark semantics.** Old `workspace/index/tests/ingest_live_composition.rs` identifies two watermark stores and a gap where the catalog only records `SourceMoved` while the driver advances its crawl clock every tick. Port or intentionally redesign this behavior before claiming restart parity.

### P2 — required for a measured, clean cutover

1. **Run a shared benchmark.** The new structural harness is valuable for engine laws, but it cannot be compared to old index benchmarks. Create one fixed corpus (at least 200 packages across the seven ecosystems, with source/IR/graph/vector fixtures), release-build both versions, and measure acquire, compile, publish, index, cold/warm query p50/p95/p99, peak RSS, allocations/copies, bytes on disk, restart/recovery time, and remote transfer/validation. Record machine, toolchain, data roots, repetitions, and result roots.
2. **Define deletion gates.** Do not remove old trees until the P0/P1 commands pass from a clean checkout, data is migrated or explicitly abandoned, and rollback has been tested. Delete by manifest reachability and `rg`-verified references rather than by directory names.
3. **Archive historical perf and migration evidence.** Preserve backend_1 index benches and workspace2 reports as immutable comparison artifacts, clearly labeling which were runnable and which were design-stage evidence.
