## Refactor contracts suggested by actual failures

- An accepted startup command produces both a present semantic surface and a new visible frame without relying on a later key or resize. First activation, route notification, occlusion, and frame scheduling require one complete lifecycle contract.
- Focus has one mounted native owner. A row cannot simultaneously be the focused node and its own active descendant; travelling visual selection must not create invalid accessibility ownership. Verify left/right click, keyboard stepping, scroll virtualization, and native reactivation on the same real shelf row.
- Each transient surface records a live initiating destination and focus owner. Escape, pointer Cancel, backdrop dismissal, and successful submission must use the same return contract; closing a child flow cannot remove Settings or strand keyboard focus.
- Action admission depends on a typed prerequisite and terminal state. Failed search Return preserves draft and recovery; enabled Graph Page/Code controls require a usable selected destination or explanatory feedback; displayed hints own their keys ahead of ordinary shortcuts.
- Persisted local project state is independent of semantic index readiness. Waiting, active compilation, refused compilation, unconfirmed prior outcome, partial dependency ingest, and ready publication are distinct visible states. A compiler hook alone is never treated as process death or successful terminal delivery.
- Layout continuity uses stable coordinates for content behind transient query/result changes. Reduced motion removes movement, but also needs a stable composition rather than an instantaneous large spatial jump.
- Meaningful visible status, validation, metadata and control values have accessible semantic equivalents. Native actions and actual pointer coordinates must verify the same behavior; probe-only success is insufficient.
