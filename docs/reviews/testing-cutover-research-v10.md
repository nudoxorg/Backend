The repository has unusually good cutover scaffolding: independent canonical/state laws, a real-process journey suite, a live GPUI adapter, explicit evidence manifests, a versioned K0–K12 plan, and an honest K12 status that still leaves old-writer fencing, compatibility replay, rollback, and deletion open. ## 1. Highest-value findings

1. **Cargo lane policy has three conflicting descriptions.** `.config/scripts/cargo-shared-cache.sh:316-320` and `docs/operations/cargo-cache.md:11-23` define four leased warm build directories, a host-wide compiler ceiling, bounded waits, and no overflow lane. `docs/operations/agent-cutover.md:147` still says a timed-out caller gets an invocation-local overflow directory, and `.config/nix/tools.nix:41-44` says `sccache` shares results with overflow lanes. Treat the wrapper and `cargo-cache.md` as executable policy; fix or mark the older prose before granting build lanes.
2. **The GUI viewport contract disagrees with the implementation.** `docs/operations/gui-testing.md:111-115` says nine sizes, while `tools/gui-harness/src/lib.rs:60-72` declares ten: 640×480, 800×600, 900×600, 1024×768, 1280×800, 1440×900, 1440×1000, 1600×1000, 1920×1080, and 2560×1440. Freeze one versioned matrix and make the Nu manifest, capture planner, report, and deletion gate consume that same list.
3. **IME is a silent no-op in the generic GPUI driver.** `tools/gui-harness/src/gpui_driver.rs:444-447` accepts `ImeText`, `ImeCompose`, `ImeCommit`, and `ImeCancel` without dispatching an event. A journey can therefore report that it ran an input step while exercising no platform behavior. Either implement a real platform event path and add composition/cancel journeys or reject those steps as unsupported on a declared platform lane.
4. **Native accessibility is a declared but unobserved source.** `tools/gui-harness/src/semantics.rs:90-98` defines `SemanticSource::NativeAccessKit`, but `apps/desktop/src/harness.rs:107-270` exports the product action tree plus measured GPUI rectangles and sets the source to `GpuiPostLayout`. `native_focus_owner` is a GPUI focus handle, not an AccessKit tree readback. A native accessibility claim needs a real post-commit AccessKit observation on each supported platform, or the acceptance contract must say GPUI post-layout is the only evidence.
5. **The visible GUI CLI intentionally cannot capture.** `tools/gui-harness/src/main.rs:59` returns an error for `capture`; live capture is only possible through the in-process desktop adapter in `apps/desktop/src/harness.rs:34-105`. This is a sound fixture-rejection choice, but it means a CLI-level GUI gate must invoke the desktop adapter and record that fact. A shell command that merely calls the generic binary cannot establish live GUI evidence.
6. **Persistence unit coverage is narrower than the process journey.** `apps/desktop/src/model/persistence.rs:176-376` has `PersistentState::load`, `save`, `cold_reload`, and `cold_settings`; its local tests at `:430-483` cover a complete atomic state and command-palette route projection. The process tests cover SIGKILL/restart and offline roots, but no local persistence test was found for corrupt/truncated JSON, unknown future fields, incompatible schema versions, failed directory sync, or a stale temporary file. Add those as explicit compatibility cases rather than relying on process startup failures.
7. **The platform crate tests Windows only.** Unix behavior is a direct `std::os::unix::net` re-export in `crates/platform/local.rs:5-11`; Windows has real AF_UNIX/security tests in `crates/platform/win32/tests.rs:33-176`. No crate-local Unix parity module or repository CI matrix was found, and `.config/nix/lib.nix:8-9` describes Linux architectures only. The release matrix must include actual Linux, macOS, and Windows runs for sockets, identity, endpoint cleanup, focus/clipboard/resize, and GUI rendering. Cross-compilation alone cannot prove native behavior.
8. **The same semantic oracle is implemented at several layers.** Full-recompute and weighted-model comparisons occur in `crates/flow/src/tests.rs:432,486,1574`, `tests/performance/tests/structural.rs:241,348,461`, and `tests/laws/tests/cutover_regressions.rs:149,207`. Root-history oracles also overlap `crates/version/src/tests.rs:999` and `crates/store/src/tests.rs:255,519`. This gives breadth but creates a duplicated test authority: fixes can update one model while another still encodes a different law. Make one small, dependency-light model the canonical oracle; have performance and journey suites consume serialized cases and compare roots/counters without reimplementing semantics.
9. **Surface process matrices overlap and do not share one owner.** `tests/journeys/tests/surface_matrix.rs:415-728` uses `tests/journeys/src/surface_matrix.rs:100-551`; `tests/journeys/tests/restart_persistence.rs:1048-1582` imports the same helper; `tests/journeys/tests/surface_interfaces.rs:551-809` reimplements CLI/MCP transport and surface cases; and `surface_parity.rs:394,793` independently compares CLI/MCP output and wrong-basis faults. Keep one shared fixture/case vocabulary, but assign semantic parity to one registrar-owned oracle and process lifecycle/fault injection to one separate owner.
10. **Dan Luu’s current dates in the older repository ledger are stale or ambiguous.** `docs/research/danluu-testing-agents.md:9-22` uses an RSS/build date for the newest article and feed dates for older pages. Dan’s current publication index gives `agentic-testing` 2026-09-07, `testing` 2015-03-10, and `broken-builds` 2014-11-10. The new report records index dates and labels claims as external evidence, never as repository policy.

## 3. GUI harness audit and GPUI CE recommendations

The production path is mostly sound. `apps/desktop/src/harness.rs` starts the same host and session as the app, hydrates a real catalog, installs `UiEntityGraph`, and calls `capture_gpui_state_with_adapters_result_and_semantics`; `tools/gui-harness/src/gpui_driver.rs:185-311` creates a headless GPUI window, applies typed input, advances a virtual clock, draws, and captures an image. This is evidence-producing code rather than a screenshot fixture.

The generic driver still hand-delivers every platform event in `apply_step` (`gpui_driver.rs:314-521`). Use the vendored GPUI CE testing vocabulary for component behavior: `#[gpui::test]`, `TestAppContext`, `VisualTestContext`, `add_window_view`, `run_until_parked`, `simulate_click`, and `simulate_event`. Reuse `MeasuredProbe`, `SizedProbe`, and `HideableProbe` for real prepaint geometry. This catches zero-height, wrong-width, hidden-slot, focus, and disabled-event defects that a declared semantic rectangle or a bespoke callback cannot see.

Keep `capture_live` and the visible-window contract for claims that require the product root, compositor, titlebar, native clipboard, actual platform focus, or resize. The generic driver should fail closed for unsupported IME steps. Add a platform adapter rather than a no-op branch. If AccessKit is part of the product promise, add a post-commit native tree reader and set `NativeAccessKit`; otherwise rename the contract around GPUI post-layout evidence and remove the unused source from the acceptance path.

The crop helper currently has a useful fail-closed rule: it rejects a renderer surface smaller than the requested physical size and upper-left crops the known fixed 2× backing surface. Its tests use synthetic images, so add a separate sentinel that places content at every physical edge and ties the crop to the captured viewport/scale manifest. The artifact verifier should remain independent of the renderer and reject stale route/root/probe hashes.

## 4. Nix, four-build lane, caches, and worktrees

The operational authority is `.config/scripts/cargo-shared-cache.sh` plus `docs/operations/cargo-cache.md`:

- Enter the pinned environment with `direnv exec . backend doctor`, `backend catalog --json`, `backend agents verify`, and `backend scope changed --json --base <train-head>` as specified by `docs/operations/agent-cutover.md:138-145`. If direnv is unavailable, use the Git flake `nix shell 'git+file:///absolute/path/to/integration#luna-tools' --command ...` and record the invocation. Use `path:.` only when the shell definition itself is uncommitted.
- Cargo final artifacts stay in each worktree’s `.local/target`; intermediate Cargo 1.97 graphs use the four-slot pool by default (`cargo-shared-cache.sh:1-4,28-43`). `CARGO_INCREMENTAL=0`, `sccache` is bounded to 8G by default, and Cargo jobs are divided across active slots.
- A canonical worktree gets one mutable build lease and remembers its warm slot. Same-worktree compile calls serialize; handing a slot to a different worktree deletes that mutable graph first (`:217-231,233-271`) to avoid stale `rmeta` and public-API leakage. `sccache` is the cross-worktree compiler reuse layer.
- When all four slots are occupied, wait at most `NUDOX_CARGO_SLOT_WAIT_MS` (five minutes by default) and exit 75. Do not create an overflow lane (`:282-320`). The same-worktree wait is independently bounded by `NUDOX_CARGO_WORKTREE_WAIT_MS`. Metadata/tree/manifest/help/version commands bypass the compiler lease; unknown commands take the conservative compiling path (`:45-61`).
- Keep `.local/nextest`, GUI lanes, native output, and evidence roots worktree-local. `CARGO_BUILD_BUILD_DIR` can be explicit, but it must remain isolated and recorded. Do not share a mutable target or warm graph between worktrees. A worktree census must record path, head, branch, dirty state, owner, target, and lease before pruning stale registrations (`agent-cutover.md:149-153`).
- Nextest policy in `.config/nix/control.nix:474-580` uses zero retries, treats flakes as failures, and serializes scarce allocator, concurrency, display, live-service, process, compiler, and telemetry groups. A group wait or typed skip leaves the affected gate unresolved; it is not green evidence.

The four-build global lane is a concurrency ceiling, not a target. Start with one source-only lane per candidate; grant a build slot only after scope and oracle review. At most four mutable Cargo graphs can be active, and the host-wide compiler memory bound must be respected even when there are more worktrees. This avoids disk/RAM waste while retaining cross-worktree compiler reuse.

## 5. Risk-weighted cutover, compatibility, rollback, and deletion

Use the existing K0–K12 order in `docs/operations/agent-cutover.md:264-279`, but make promotion risk explicit:

| Order | Scope | Entry gate | Exit/canary gate and rollback |
|---|---|---|---|
| **R0/K0** | Clean base, policy root, contracts, oracles, worktree/caches | Exact source/config/control digests; one owner per path; model and hidden-case registries frozen | Scope/evidence receipts are reproducible. No product merge. Revert candidate branch, preserve receipt.
| **R1/K1** | Version, canonical keys, store, journal, pack, root/fence | History-independent IDs, wire version grammar, budget-before-publish, crash/root recovery, old/new fixtures | Integrate behind old-store adapter. Code/read rollback is allowed; data-head rollback requires intent replay proof.
| **R2/K2** | Flow, weighted batches, arrangements, frontiers, retractions | Independent full model, generated semantic edits, SCC/support laws, bounded work, mutation red tests | Keep new flow non-authoritative. Revert to old computation while retaining candidate roots.
| **R3/K3** | Local vertical and desktop/CLI/MCP | Real locald, live index, root/route/action parity, cold/warm/fresh/offline journeys | Shadow old and new; old result remains authoritative. Revert read pointer; retain candidate state for diagnosis.
| **R4/K4** | Native compiler authority and seven language leaves | Manifest/toolchain identity, complete/partial/unavailable semantics, cold/session parity, native crash corpus | One language/package canary. Fence leaf on mismatch; use old authority and durable intent replay.
| **R5/K5** | Projections: docs/name/search/graph/source/statistics/vector/UI | Every facet has a dependency key, deletion/retraction result, top-k tie policy, exact fallback | Derived reads canary; discard/rebuild derived cache on rollback. Never hide a stale row behind a healthy process.
| **R6/K6–K8** | Planner, replication, remote/memo/hedge | Admission, fences, cancellation, bounded resource/waste, stale/corrupt/partial network cases | Remote is acceleration only. Disable remote cohort and continue local promised work; reject unmatched receipts.
| **R7/K9–K11** | Recursion/vector, sessions, physical layout | Exact oracle/recall bound, cold/session equality, hidden workload distributions, root equality before timing | Roll back implementation/read path; preserve canonical data head. Keep subprocess/local fallback.
| **R8/K12** | Shadow, dual-read, atomic writer, deletion | Full compatibility matrix, old-writer fence, rollback drill, soak, all platform/product/fault rows green | Pause admissions, drain/fence attempts, atomically move selected head, retain bridge/artifacts through deadline. Delete only after gates below.

Storage policy for greenfield versioned state:

1. Version independently: logical intent journal, canonical key/order/hash domain, root/state identity, authority manifest, recipe/facet, wire envelope, pack/journal layout, and derived cache. An intent must be understood by old and new writers or be rejected before acknowledgment.
2. Test the promised directions explicitly: old reader/new writer, new reader/old writer, old writer/new reader, new writer/old reader, unknown version/field, interrupted write, export/import, and replay. A layout-independent intent journal and compatibility export are prerequisites to a data-head rollback.
3. Keep exactly one writer for a canonical head. Old and new writers may shadow or dual-read in isolated namespaces; they must never race on one head. Candidate results are addressed by schema, input root, recipe, and run ID.
4. Separate rollback of code/read behavior from rollback of data. Code/read rollback can point back to old code while retaining the current durable head. Data-head rollback is permitted only when no acknowledged intent is lost; otherwise replay every acknowledged intent into an old-compatible root first. Remote receipts require destination idempotency or reconciliation; a local receipt alone is not exactly-once.
5. Derived caches, PNGs, indexes, and remote memo artifacts may be discarded and rebuilt only when their root, recipe, and authority are retained. Durable roots, intents, fences, and audit receipts stay through the declared retention window.

Deletion gates are all required, not a checklist from which one can choose: final owner and deletion commit; versioned schemas and export; shadow/dual-read all promised cases; one writer and intent compatibility; old/new fault matrix; seven-language cold/session matrix; local/offline capability; K0 performance/work/RSS budgets; GC/pin/reader/evidence reachability; and a successful rollback drill from the last pre-deletion release. `docs/operations/cutover-evidence.md:51-72` already marks K12 open on external old-writer fencing, compatibility export/replay, rollback drill, and final deletion. Preserve that red status until receipts exist.

Production readiness requires zero unexplained shadow mismatch over a representative soak, no affected matrix row left `unknown`, zero acknowledged-intent loss, successful cold/fresh/restart/offline/partial-failure journeys, live CLI/MCP/desktop identity equality, real Linux/macOS/Windows evidence where promised, p50/p95/p99 and retained-RSS/work budgets within declared limits, alert/revert drill, and a recorded retention/deletion deadline. `git diff --check` and clean controlled builds are necessary repository hygiene but do not substitute for semantic or rollback evidence.

Regression triage preserves the smallest input, generator seed, schedule, work key, old/new roots, authority/fence, process/platform, artifact hashes, and raw transcript. Classify first as identity, delta/retraction, coverage/authority, durability, compatibility, concurrency/fence, resource/work, latency, product, or operations. P0 is acknowledged data loss or an unsafe writer; P1 is stale/forged/incorrect-authority output, duplicate external effect, or rollback failure; P2 is a product or platform contract failure; P3 is evidence/diagnostic drift. A red mismatch freezes the affected cutover scope, shrinks and retains the case, and only then permits a fix. A flaky run is a failure with seed/schedule/resource-group ownership; retry cannot convert it to green.

## 6. Luna implementation delegation protocol

The existing role model in `docs/operations/agent-cutover.md:25-34,260-281` is useful if the cell boundary is enforceable. Terra owns architecture, schemas, dependency DAG, and registrar-held oracles. Luna owns a narrow leaf. Terra reviews from a fresh context. Sol integrates only accepted receipts.

**Source-only phase.** Give Luna a frozen contract digest, exact owned paths, dependency facets, public fixtures, failure dimensions, model/oracle description, and expected evidence fields. Luna may inspect the checkout and edit only source/docs/fixtures within the lease; no Cargo/Nix/build/test artifact is allowed. The deliverable is a small patch plus a machine-readable plan: changed paths and hashes, public API/schema version, ownership assumptions, affected matrix rows, generated cases and shrinker, expected failure modes, rollback behavior, and commands reserved for the granted lane. A source-only reviewer rejects out-of-scope edits, copied oracles, hidden global state, new shared target/cache paths, and tests that only restate the implementation.

**Build-grant phase.** After source review and evaluator admission, assign one of the four global Cargo slots, one canonical worktree, one nextest resource group, and one evidence root. The lane records Nix/direnv invocation, toolchain/control/GPUI digests, worktree/head, slot/lease owner, seed, timeout, and raw output. Same-worktree compiles serialize; an occupied global pool waits and exits 75 rather than creating a fifth graph. Build output and evidence are not copied into source or another worktree.

**Slice rubric.** Score every slice against the same questions: (a) contract/schema and version boundary are explicit; (b) ownership and dependency direction are respected; (c) implementation satisfies the law on valid, delete/re-add, reorder, partial, and malformed inputs; (d) oracle is independent and mutation-tested; (e) persistence/failure/rollback behavior is specified; (f) resource and latency counters are measured without omitted work; (g) product/API/platform evidence covers the affected matrix; (h) diff is narrow and reproducible; (i) evidence package is complete. Any unresolved item is `unknown`, not a pass.

**Evidence package.** Require `evidence.json` with schema version, cell ID, candidate digest, integration head, worktree, owned paths, dependency/control/config/toolchain digests, commands, environment/platform, seeds/schedules, case IDs, oracle identity, baseline/result roots, changed/retained rows, resource counters, artifact/transcript hashes, failures and known gaps, reviewer IDs, and rollback instruction. Store raw output separately under the isolated evidence root. A pass says what was observed; it does not assert production promotion.

**Adversarial review.** A reviewer from a different context receives the public contract and model, not Luna’s explanation or hidden fixtures. It adds a delete/re-add, reorder, stale/partial authority, cancellation/crash, wrong fence, malformed/oversized frame, and concurrent schedule. For GUI slices it adds a focus/resize/scale/reduced-motion case and inspects PNG plus semantic probe independently. The reviewer also checks tree digests before/after and tries an out-of-scope edit. A single failed holdout freezes the cell and all dependent cells until the minimized case is retained.

Conflict-minimizing ownership is path-based and semantic: one Luna per stable key/algebra law, one per language authority, one per projection/facet, one per transport state machine, one per GUI component/contract. Shared schemas/oracles are registrar-owned and merged first; no two cells edit the same schema or helper. Agents do not repeatedly rebase against a moving contract. Sol advances the integration ref with compare-and-swap against the exact receipt head.
